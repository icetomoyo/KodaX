## 4. 结果：完整受控恢复阶段，不是完整自由工程任务

token为provider返回的 input+output 总和，包含后续响应与输入中的缓存token。
耗时为该单元请求墙钟时间之和，不含人为pilot审查等待，不代表完整Runtime任务墙钟。

| 模型/场景 | 当前默认：响应/总token/请求耗时 | v3：响应/总token/请求耗时 | 质量与完成情况 |
| --- | --- | --- | --- |
| GLM / 计划继续与报告 | 1 / 14,403 / 12.60s | 1 / 13,670 / 7.62s | 都准确报告相等缺陷及2通过1失败，未假称修复；都未核对可能变化的Todo状态 |
| GLM / 拒绝恢复 | 2 / 28,398 / 13.69s | 2 / 26,840 / 9.20s | 都只读一次允许文件，正确报告相等行为及3个未收回子任务 |
| Kimi / 计划继续与报告 | 2 / 27,854 / 15.85s | 2 / 26,413 / 10.85s | 都复用计划、刷新一次后报告；默认臂把相等边界夸大为“延迟一个时间单位”，v3未作该断言 |
| Kimi / 拒绝恢复 | **3 / 40,692 / 4.65s；未收尾** | 2 / 25,560 / 6.87s；收尾 | 默认臂连续3次提议读取相同文件，v3读取一次后正确报告 |

前三个完整配对在响应数相同的情况下，阶段总token分别少约5.1%、5.5%、5.2%。
第四行默认臂为预算截断前缀，**不能把40,692和25,560解释为两个完整任务的节省比例**，
更不能因为其4.65秒更短而称它更快完成。

GLM实际首个诊断输入token为14,236→13,440，与16,379→15,522的启发式计数不是同一计量。
缓存暖度/调用顺序不同：例如该GLM配对 cachedReadTokens 为0→9,792。
所以表中耗时是观测值，**不能归因成紧凑提示的稳定加速**。

总计 **15次物理请求、203,830 token**，未知usage为0；SDK订阅路线参考折算约USD0.004826，
不是账户增量账单或已核验市场价格。预算未用满便停止，没有为失败臂追加第4轮或重跑挑成功。

## 5. 反例归因与决定

盲评时已判 Kimi 诊断B优于A（较少无依据外推），恢复A优于B（少重复读取且完成）。
揭盲后这两个较好侧都是v3，但**每组合只有一次样本，不能断言prompt消除了旧问题**。

重复读取的历史已检查：两个成功read结果与各自tool_use_id正确配对、完整存在；无状态变化、
未改写参数、无传输错误或未知usage。同一adapter其他单元成功收尾。未发现评测回执遗漏，
但仍不能分清单次模型波动、provider行为与prompt影响，归因为 **inconclusive**。
它发生在默认臂，不是此次精简诱发回退的证据；也不能据此宣布v3全面更聪明。

GLM两侧均未刷新最后看到的in_progress里程碑，用户诊断报告正确，但AMA计划一致性覆盖
仍有共同不足。对这项不能以“双方都一样”替代应有的完整验收。

当前建议保持候选，不改默认：先整合三族契约归属与partial能力边界，再冻结下一份有实质收益
的完整候选；复用本轮原始证据，不为857反复扩样。完整真实编辑、测试、子 Agent 自主恢复与
AMA收尾仍需独立最终验收，统计root/child/辅助全部请求与实际任务墙钟；本轮未声称已完成。

### 质量与反例

- GLM默认公开13/13（新增12），候选10/10（新增9）；Kimi两侧12/12（各新增11）。
  数量不代表覆盖优劣：四套新测试分别放回原始有bug的实现独立运行，均实际失败，失败数为
  6/5/3/6；结合共同oracle确认不是只写了对当前实现恒真的测试。没有改写模型生成测试。
- Kimi两侧child都明确报告README被拒绝，并改读其他合法证据；root独立读取README并整合。
  候选root识别了child读到并发修复后的状态，没有把它冒充修复前证据。
- GLM两侧child都在read拒绝后用允许的shell `type README.md`读回同一文件。原始参数保留，
  没有执行越界或禁止命令；这证明**工具级拒绝的替代路径恢复**。本fixture只拦read，不能用它
  宣称跨工具资源拒绝不可绕过；错误文字的“target unavailable”比实际fault范围更广，是
  eval-design限制。生产隔离未修改，不因为模型拿到信息就把这项限制记为通过。
- Kimi候选报告把新增11项写成10项，最终12/12总数正确；保留这项小型报告不一致。
  Kimi默认child提出examples可删和零TTL永久的建议，root没有采纳，最终遵循README并保留文件。
  child提示未改，但root生成的objective可能间接影响子轨迹，不能以“未改child”排除全部间接影响。
- GLM候选主响应减少2次，child多3次：在读取后又分轮grep到期条件、导出/时钟、examples引用；
  合计多1请求、约18秒。Kimi候选合计少3请求。单样本无法分清派发措辞、模型波动和prompt效应，
  **不能确认全任务往返/耗时非劣**，也不能把GLM约2%已知token降低解释为已经更高效。

结论继续 **recommend-iterate，保留实验候选，不进入生产默认**。已有受控配对和本次真实任务
证明该候选值得保留，核心修复未观察到损失；它们不构成“智能等价、全任务效率保证”。不为857
反复追加模型样本。后续优先利用现有轨迹完成结构性契约审计，并把需要大收益的下一完整候选
与最终模式验收合并；仅为修评测措辞不重烧本批模型请求。
