## 结论与适用范围

四格各运行一次，没有重跑、fallback、追加预算、修改模型参数或输出。GLM Agent 完整完成；
GLM Script、Kimi Agent、Kimi Script 被评测范围守卫提前终止。后面三格不是完整任务，
不能把较少请求、token 或耗时当成效率提升。**尚不能确认 Agent/Script 的质量与全任务效率非劣。**

三次中止发生在禁止命令执行前，离线对原参数重放策略也复现；这是评测拒绝反馈设计的限制，
不是 provider 传输失败，也没有证据证明底层工具能力失效。特别是不能因为被硬中止后未恢复，
就判定模型不会恢复。运行时没有向模型提供这些拒绝后的继续机会。
模式是否影响工具选择仍是开放问题：两个 Script root 都先使用保留的原生 bash，
因此更多接触到本夹具的严格 shell 白名单；不能仅凭这个关联断言模式导致智能退化。

建议 **recommend-iterate**，对象是评测拒绝反馈与尚未完成的模式资格验证。
产品 AMA、全部底层能力、SDK、专用角色及 Coding 默认保持不变；紧凑教学仍不进入默认。
不因本批结果新增发现调用、强制计划步骤、固定复核回合或删除工具。

## 完整方案剩余工作

1. **先修评测的拒绝反馈，不扩大可执行范围。** 被拒命令继续不执行，原参数/拒绝原因直接返回模型，
   区分可恢复工具拒绝与预算/取消等真正终止条件。用本批echo、for、fc、mkdir原轨迹离线验证
   “拒绝→合法替代→测试→AMA收尾”，并覆盖外部路径、保护文件、子Agent只读和预算终止。
   不通过教模型专用白名单、重写参数或额外发现调用让测试过关。
2. **上述离线验证后再决定最小补测。** 另建revision，仅补当前未完成的模式资格格；本批没有补跑。
   不重跑已完成GLM Agent来刷结果；若要作严格模式优劣比较，需要另行明确同版本对照设计，
   不能把历史Coding和本批硬拼成A/B。
3. **Linux/macOS原生发布包验收仍缺。** Windows ZIP/npm离线证据保留，CI接线不等于跨平台已运行。
4. **默认采用决定仍缺充分证据。** A–E功能和离线边界已实现；紧凑教学候选及全任务效率非劣未获确认。
   先补可信验证，再决定是否采用进一步精简；不把“保留能力”当成已证明智能等价。

本批仅扩展手动评测驱动及文档；执行前测试类型检查通过，复用上一批84项离线边界证据。
没有新增产品配置或调整生产执行策略。结论和余项同步回完整计划。

## 后续离线修复：拒绝反馈（2026-10-25）

用户随后授权先修离线拒绝反馈，不扩大可执行范围。先写真实Runtime反例，旧实现因首条echo

不走此旧反思注入链。不是GLM波动、传输失败或新评测拒绝反馈造成的。

已用无模型的真实Runtime对照复现：Coding/Script各固定三次合成响应，读取相同三文件、
