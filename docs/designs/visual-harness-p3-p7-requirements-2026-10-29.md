## 2. P3：多观察对比与像素核实

目标：模型能围绕一个问题按顺序检查多个历史时刻/区域，并用有限数值采样核实颜色或网格细节。主要复用 [visual-tools](../../packages/agent/src/media/visual-tools.ts)、[visual-raster](../../packages/agent/src/media/visual-raster.ts)、[观察 owner](../../packages/agent/src/media/visual-observations.ts) 和 [输出预留](../../packages/coding/src/task-engine/visual-output-reservations.ts)。

**实施要求**

1. 扩展现有 `visual_inspect.views`，增加 `visual_read_pixels`；保留单 view 兼容性。沿用 Agent/Coding/Script 的普通 native/checked bridge，不自动扩大 Script 叶白名单。
2. 按主设计 §6，先采用每调用最多 4 个 view、**所有 view 合计最多 4096 个样本**的内部护栏；不是每个 view 各 4096，也不是最优参数承诺。数量合规不代表剩余容量一定足够。
3. 坐标仍为原 raster 左上角整数半开区间。像素按等分网格格心读取，rows/columns 不超过选区高/宽。使用原件解码值，不从缩放结果反测、不做隐式量化/透明背景合成。
4. inspect 与 pixels 共用严格解码 profile、方向/位深/alpha 语义及 IHDR 预检。先支持 P2 的 PNG profile；扩展格式不是 P3 的前置条件。调色板用精确 RGBA 去重和整数索引，不设 64 字符等隐式颜色上限。
5. 一次调用内复用同源解码，逐源控制工作内存；不要同时保留所有历史大图。复用已有 owner 与取消结算，不先造跨 Run 缓存或 worker 池。
6. 在生成重结果前预留整次调用的图片/数值输出，并与兄弟调用共享额度。像素坐标、RGBA/调色板、标签和错误包装都计入预计文本大小；不能给像素表套用 1500/图，也不能在编码后才发现完全装不下。
7. 参数错误在开始重工作前整体拒绝；执行期间的缺失、hash 不符或其他局部失败，按请求位置标为 partial/error，不错位、不偷偷换图。取消和失败结算幂等，已产生且保留的输出不能提前释放额度给兄弟调用。
8. 数值工具不默认附送原图或调用第二个模型。图片路由检查只用于实际返回 image 的路径，不能把 inspect 的图像门槛机械复制成“文本数值结果也不可用”；每条实际支持路由按其输出合同验证。

**验收重点**

| 必测路径/反例 | 通过依据 |
| --- | --- |
| 同一原图两个区域、不同原图、同来源不同时刻、重复选择同一观察 | image blocks、标签、observationId、映射和错误槽位严格对应请求顺序；检查不增加源事件、不刷新 current |
| 小型手工已知 RGBA raster | 独立预期值验证格心坐标、边缘像素、alpha=0/部分透明、超过 64 种颜色；不以被测采样函数生成 expected |
| rows/columns 越界、零面积、总样本越限、超 profile/坏 PNG | 在解码或重输出前拒绝；原件仍在；P2 重复 IHDR、CRC、位深/尺寸反例继续通过 |
| 多 view 加并行兄弟调用，含重复 provider call ID | 总额度不超发；失败/取消不重复退款；实际解码结束前不重开资源槽；最终 tool/result 配对与 capacityDebt 保持原义 |
| 中途原件缺失/损坏 | 有序 partial 结果能明确哪些项失败；不把部分完成记成全部通过 |
| 真实公共工具→Runner→生产 serializer | 三模式 native/checked bridge，所声明协议的多图 payload 包含正确 bytes、数量、标签和顺序；数值结果不被结果截断悄悄变成不完整表 |

建议把多 view 检查和数值工具做成两个可单独验证的小提交；共同使用同一边界，不复制两套解码器。P3 完成须更新工具合同、支持矩阵和完整首轮字段计量，不能只改 schema 的 maxItems。

## 3. P4：产品输入与长任务完整性

目标：将已验证的 immediate 路径扩展到声明支持的产品输入/分支，在压缩、重启和环境变化后仍有正确证据与适用状态。接缝见主设计 §5、§7、§9；主要位于 [Runtime](../../src/sdk-runtime.ts)、[输入接纳](../../src/runtime-visual-input.ts)、[visual-owner](../../packages/coding/src/media/visual-owner.ts) 与 [storage](../../packages/repl/src/interactive/storage.ts)。

**实施要求与验收**

- **queued / after_turn / redirect / steer**：逐个列出实际入口与接纳时点，不用一个入口替其他入口背书。承诺“接收时那张图”就应在既有入队/接纳边界固定 bytes 与回执；之后即使原路径被覆盖、删除、进程重启或排队延迟，交付仍取同一快照。已有 inputId 的同意图重试复用原件，异意图仍拒绝。
- **队列的持久性和可见性分别验证**：入队保存成功不等于已进入当前模型上下文。撤回、重定向、失败重试、多个输入合并不能让未交付或已撤回的图出现在错误会话/分支，不能复活已取消输入。沿原 pending input owner，不建第二日志。
- **fork 正向继承**：分叉前可见观察可回取；分叉后各支隔离，旁支和执行前 entry 看不到未来图。保留 observationId 的稳定性，同时正确映射新的 owner/lineage，不能依赖会重编号的物理 entry ID。删除父 Session 后子分支仍满足已承诺的保留语义；优先复制需要的原件，避免为此引入全局引用计数系统。
- **重复压缩/sidecar/重启**：不仅单次 compact；至少覆盖多次压缩后的历史回取、旧岛内容 evict、完整 lineage 加载、回退及 Script 恢复见证。digest 通过不替代 bytes/receipt 的完整性与提交证明。
- **续接状态**：模型获得继续所需的观察引用、适用认识、最后动作/结果和必要真实图片。复用已有任务状态/摘要，避免把整份图像目录和所有图片每轮塞回。reset、episode/来源版本变化后，旧临时坐标、进度及假设不能继续作为当前事实。
- **生命周期**：archive 保留；真正删除走原 owner 清理/重试；媒体缺失、过期、hash 不符明确报告，绝不回退读取当前同名路径。覆盖清理失败与分支保留，不能误删仍可访问的原件。
- **报告边界**：task report/UI 只带结论及引用，不能成为唯一媒体收据；父 Agent 需要看图时走授权回取。不能因为报告里有附件引用，就宣称父 Agent 已取得真实图片。

以上需通过真实 Runtime/storage 输入与恢复路径做测试。对尚未实现的输入/宿主保留明确限制；不要用放宽 owner 检查来让 fork 测试变绿。

## 4. P5：按需扩展来源与宿主

目标：让现有更多产图入口复用同一观察合同。依赖 P4；每种来源是独立交付，不要求全部完成才能采用基础版。

建议先评估现有 MCP 和 Artifact 的实际需求，再决定额外 Host/standalone 接线。实施前记录本片明确选择的来源；未选择者标为待接入，不把“P5”当作所有平台均已支持。

| 来源 | 必须交付/验证 |
| --- | --- |
| MCP typed image | 在仍持实际 bytes 的接纳点固定原件，绑定精确调用与 image ordinal；多图、重复交付、取消、恢复、权限和主模型输入均走原生产链 |
| Artifact | 保留原 provenance/locator/依赖；源文件变化后，当前 readEvidence 仍拒绝旧证据，而历史 inspect 能回取已接纳快照并标 historical。不得为历史回看放松当前验收 |
| Host string/structuredContent 桥 | 显式可信媒体 materialization，不能把 JSON 路径或字符串当图片；用真实 Host 往返证明 bytes、owner、权限、故障和恢复。缺通道则明确 unsupported |
| standalone SDK | 使用注入 owner/提交/预留的窄合同，证明不依赖 Runtime/REPL/Space；单 Run 内存宿主与 durable 宿主分开声明，未接持久化不能承诺跨重启 |

每个来源覆盖“源文件变了、旧观察仍是旧图”的反例及真实 serializer。记录实际支持格，不扩展成所有 provider×所有模式×所有宿主的无差别矩阵。

## 5. P6：一个受控动态闭环

目标：验证“旧图检查、重新观察、为获取信息而行动”三个不同操作可以组成可靠闭环。先选择一个可重现的小型环境/现有消费者，写清来源版本、动作、副作用、采样时点及是否可暂停；不以 ARC 分数、完整桌面平台或实时帧率作为完成条件。

至少有一个经生产工具装配、权限和 owner 的可运行演示；确定性 fixture 可以控制环境状态，但不能只测一个绕过生产执行链的 helper 就宣布 computer use 已支持。

**硬验收场景**

1. 根据观察 A 发起动作，动作前核对 expectedObservationId/来源版本；两个都基于 A 的动作排队时，后一个不能仅因拿到锁而继续。
2. 动作前启动、动作后才返回的旧采样，不得覆盖新的 current；不同来源分别维护自己的当前依据，不设置全局唯一 current。
3. 动作已执行但采图/归档/回传失败，保留已执行或 unknown，旧 current 失效；恢复后补观察或停止依赖该状态的操作，绝不自动重放动作补图。
4. 取消与断连分别覆盖未派发、已派发未确认、已完成；复用 Host invocation 状态。本地 adapter 不走 Host 时也要提供可核对的副作用事实。
5. native 的 serial 声明通过 checked bridge/兼容入口正确传播；同时证明 serial 只负责批次执行分类，跨 Actor/Run 的环境时效仍由同一环境 owner 处理。无关来源/历史检查不被全局串行化。
6. 一个明确演示：初始图留下歧义，探索动作或补采样提供可区分的证据，再核对结果。机械测试只能证明闭环接线；“模型主动选择了正确探索”留给 P7 行为证据。

能力限制必须写清：锁只能保证 owner 内顺序，不能保证外部持续变化的桌面在动作时仍与截图一致；需要焦点/状态复核的来源由 adapter 提供。环境重置后，旧历史仍可读，但不能当新动作依据。

## 6. P7：成本与行为价值评审

基础版最终评审依赖 P3、P4、P6；若宣称支持某个 P5 来源，再加入该来源验收。离线成本、机械回归与负例随片更新，不等全部开发完成才开始。严格遵循 [EVAL_GUIDELINES](../../benchmark/EVAL_GUIDELINES.md)；本文件没有发起付费实验。

**先把三个问题分开：** 工具是否正确由 Layer 1 回答；模型是否按需取证/修正判断由受控行为 probe 回答；远端协议是否接受图片由必要的在线兼容 smoke 回答。三者不能互相替代。

**比较基线与成本**

- 保留原 P0 冻结基线和 P0–P2 成本文件；新增以 `30310e00`（或接手时明确记录的后续基线）对比候选的证据，可同时报告累计增量。不要改写旧 hash 或把旧抓包变成本次实测。
- 按三工作面捕获完整 system/messages/tools 及 Script 内嵌合同，报告新增 schema/指导/图片标签；未装配 owner 的 SDK 路径继续检查不增合同。没有视觉输入或调用时，不新增截图、目录扫描、解码、轮询或模型请求。
- 图片数量、尺寸、bytes/hash 与本地解码/编码耗时独立记账；实际 usage、缓存命中、费用、请求数与全任务耗时另列。不把 base64 文本估算、1500/图或提示缓存等同真实视觉费用。
- 工具/提示变更后重新捕获受影响的 fixture；构建体积与启动依赖继续检查。若触及现有体积门槛，先查新增依赖与加载位置，再解释取舍，不能默认不断抬高上限。

**最小行为问题集合**

| 问题 | 应观察什么，而非只计调用数 |
| --- | --- |
| 小细节不清 | 能否选中相关局部，取证后判断更准确；放大无关区域不算成功 |
| 旧画面/新假设 | 能否选择正确历史时刻，而非把当前图或摘要误当旧证据 |
| 颜色/网格核实 | 能否选择合适采样区域/密度，正确解释数值与采样局限 |
| 动态歧义/过期依据 | 能否补观察或探索并依据反馈修正，遇到 unknown 不重复动作 |
| 不需要视觉 | 文本/结构化数据已足够，或有图但与任务无关时，不做无用检查；不能承诺模型永不误判 |

每次实验预先冻结生产工具真实字节、模型/路由、图片 hash、初始自动展示帧数、历史、样本量、判断 rubric 和停止条件。工具主动回取带来的证据差异是候选机制的一部分；不要额外给候选更好的初始图，从而混淆效果。

先用 1–2 个代表 case、1–2 个 provider 做最小 pilot；Layer 2 只捕获下一响应、不执行自由循环，取证后判断可用单独固定历史检查；确需连续反馈时用默认不超过 3 轮的预定义 Layer 3。端到端 smoke 最多 3 case，不用于 prompt A/B 或普遍智能提升结论。

运行前必须给出总调用、每 cell 调用/轮数、单次输出 token、总 token、外部费用及 timeout 上限，并遵守实际 provider 并发策略；不能只写“有 timeout”。执行付费部分须落在用户已有授权与冻结预算内，缺失时先交付机械证据和可执行实验方案。

由负责实施的主会话盲化读取配对 raw，记录任务有效性、实质提升、可信回退和原因，提出采用/迭代/撤回或实验无效的建议。不要自动加一轮外部 judge panel；不要以工具次数、退出码或单一通过率宣布变聪明。raw 放 OS Temp，必要分析和证据 hash 进入正式记录。预算或授权不足时报告 P7 行为部分未完成，不能以 Layer 1 全绿替代。

文档状态同步要求：保留主设计原审读日期与研究边界，用新增状态/实施记录说明已实现部分，不把整份设计改写成已经验收。正式跟踪文档不能只依赖未跟踪文件或 ignored research；提交前核对依赖文档是否随本分支保留。不要把其他线程的修改一并提交。
