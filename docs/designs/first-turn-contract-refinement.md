## 最终范围

- CLI/REPL 使用 AMA，移除 SA 帮助、补全和切换入口；旧显式 SA 命令返回退役说明。Runtime Product API 未指定时默认 AMA，SDK 显式 SA、在途 Run、queued continuation、child/helper 的直接执行器继续兼容。
- 保留已有 Worker 规划、恢复、派发、终止和验证责任。简单任务原有直接执行、免 Todo 指导继续生效，不新增任务分类器、AMA-lite 或固定多阶段流程。
- 仅精简 `ask_user_question`、`todo_create`、`todo_update` 的重复描述。参数结构和 handler 不变，稳定 id、增量更新、owner、veto、metadata/null、语言及自由文本/批问规则保留。
- 全部 native schema 和完整 `spawn_agent` 契约保留。五项完整 schema 延迟披露和派发说明缩短的试验已撤回；较大候选的降幅不能当作当前结果。
- 按真实 Actor 绑定统一 builtin 协作能力展示，保留 SDK 注入和独立 extension override。修复 bridge→bash 串行调度、重复 provider call id 的执行事实归属、AMA 工具上下文/MCP 交互以及根上下文用量事件。修正过时的权限模式教学。

未删除 `multi_edit` 或其他执行能力来追求工具数量目标；现有编辑批处理、文件锁、权限、取消、压缩和恢复底座保持。内部已退役空链路另经引用/导出审计清理，30 组 Worker 提示字节相同，不计作 token 收益。

## 完整请求测量

同一生产 SDK Runtime/Host/ClientPlane、相同 Windows 夹具，捕获实际 SDK fetch 的序列化 body；OpenAI 与 Anthropic 均保留 58 个 AMA 工具。工具、说明、管理消息、任务和包装全部计入。

| AMA 协议 | 基线 bytes / 估算 tokens | 最终 bytes / 估算 tokens |
|---|---:|---:|
| OpenAI | 91,963 / 23,067 | 88,518 / 22,204 |
| Anthropic | 90,384 / 22,672 | 86,939 / 21,809 |

每个完整请求减少 3,445 bytes、约 863 估算 tokens（约 3.8%）。这是统一 `countTokens` 的请求规模估算，不是 BPE、API usage、Codex 桌面上下文数值或端到端加速结论。零外部请求的可执行测量见 `tests/first-turn-wire-inventory.test.ts`。

参考规模：Codex CLI sol/astra 的完整 Responses 请求约 17,182–17,271，DSH Standard 8,776、PTC 11,145。能力、skills 和协议不同，不能换算为严格效率倍率；KodaX 当前仍比上述 Codex 场景多约 4.5–5k，未达到输入量持平。

## 验证与有限模型评估

执行遵循 `benchmark/EVAL_GUIDELINES.md`：先零网络契约与真实 handler E2E，再固定历史、真实 production 工具字节的盲化配对，由主会话先评审再揭盲；有界 Runtime smoke 只验证执行，不用于 A/B 质量裁决。

- 全量回归记录 16,687 通过、89 跳过；运行期间撤回派发描述候选导致 3 项旧快照断言失败，最终恢复版本的 registry 全文件 37 项重跑通过。最终全部改动相关测试 480 项通过。未将前述全量运行写成零失败。
- 类型检查与完整构建通过，最终构建产物定向回归 22 项通过；实际 CLI 帮助无模式选择，显式 SA 返回退役错误。真实 Runtime E2E 覆盖入口/在途引擎、native/bridge 调度、工具发现后桥接执行、取消/恢复及 MCP；脚本化响应的实际 read→批量 edit→Node test→final 编辑闭环通过。
- tool-search、tool-resolution 和证据 writer 三模块定向覆盖：64 项测试通过，行覆盖 96.63%、分支 94.48%；这是指定模块覆盖，不冒称全仓覆盖。
- v3 两模型四对固定历史样本出现混合效率差异；v4 保留 native schema 后，GLM 仍倾向基线的并行推进。因果未证实，但据此保守撤回 schema 延迟与派发说明缩短。
- 最终 v5 只改三项描述，GLM 广域审查一对盲审为持平：两臂均取得已有审查证据并派发只读 cache 审查，候选多一次 wait，未测得实际总等待成本。此前 Kimi/GLM 的较大候选样本不改标为最终候选结果。
- v5 首次 smoke 的 Windows 证据路径比较错误导致两次已付费响应未能落盘，工具尚未执行；标为 `eval-invalid`，保留全部费用和失败 Runtime 夹具，不能算模型成功或失败。writer 经实际函数离线回归及落盘探针修复后，v6 继承账本和原配对评审，仅使用剩余四次请求。
- `kimi-code/kimi-for-coding` 和 `zai-coding/glm-5.3` 各完成一次两响应的实际 AMA Runtime smoke：执行真实 Node 回环网页夹具测试，随后准确报告退出码 0、1 个测试通过；服务器各收到一次请求，无文件修改、重试或子 Agent。工具可见性限定为 bash，这不证明开放任务质量。

首批累计 **18 次请求、269,986 tokens、$0.009479795 冻结费率参考成本**，未知 usage 和未结算预留均为 0；该金额不是 coding-plan 订阅账单。12 次配对探针请求、2 次持久化失败、4 次最终 smoke 全部计入，没有重置历史费用。冻结上限为 18 次、600k tokens、$1；每次输出 2,048、120 秒，每 provider 一并发，禁止自动 retry/fallback。

工程建议是保留当前窄改动。当前未观察到最终配对中的任务语义错误，两条受控实测执行闭环通过；不能据此声称广域智能非劣或整体更快。首批结束时缺少的最终 live 编辑 smoke 已由下述 v7/v8 补齐；最终候选 Kimi/计划恢复 A/B、Flash/DeepSeek 等路线仍未覆盖，不为补齐矩阵继续烧 token。后续若有实际任务回退，先读取保留 raw 定位，再只复验受影响场景。

## 最终真实编辑补验登记（v7）

用户追加要求补齐最终版本 live 编辑闭环。本次固定生产版本 `4c4c3774`，不改产品提示词、schema、规划或派发策略；只为既有 eval helper 增加完整工具表选项，旧测试默认仍用核心工具。已完成 RED→GREEN，含完整工具表的脚本化实际 AMA 编辑闭环、writer/停止/越界回归共 7 项，以及源代码和测试类型检查。

补验为 Layer 3.5、两个 case（Kimi/GLM 各一个相同夹具），不做 A/B 或外部模型裁判。两条已有路线为 `kimi-code/kimi-for-coding` 与 `zai-coding/glm-5.3`。57 项完整 native 工具表下，四个依赖响应分别读取 `sum.js`、一次 edit 原子修复加法/乘法并保留字节格式、执行 `node --test sum.test.js`、依据真实结果报告；实际操作只允许目标文件与该命令。四轮是验证这四个依赖步骤所必需，不开放自由 task loop。

追加最多 **8 次请求、每路线 4 次、参考成本 $0.05**；继承上一批已结算 18 次及费用，累计调用最多 26 次、tokens 仍限 600k。每请求输出上限 2,048、120 秒，每 case 300 秒，同 provider 在途 1、不同 provider 并行，0 个 child，禁止自动 retry/fallback/repair。离线完整输入约 20.8–21.3k 估算 tokens/轮，预计新增约 0.17–0.2M tokens、参考成本低于 $0.01；不是订阅账单估计。

Layer 1 已验证真实工具接线与落盘，不能回答真实模型能否给出有效编辑参数并准确整合测试证据。生产 commit/tree、支持脚本与 driver 哈希、真实路线/费率、夹具与 rubric 在付费前冻结；逐轮输入及原始响应先落 OS Temp 再执行工具。出现 provider/usage/图顺序/路径/测试/落盘问题即停止两路，保留已在途响应与全部收费，不自行补齐矩阵。主会话将读取每条 raw、实际工具结果、原始/最终字节和 TAP 输出，分别判定任务有效性、修复、范围和报告诚实性；小样本仍不证明全局智能非劣。

v7 结果：Kimi 四响应真实编辑闭环完成；GLM 读取和一次双替换成功，第三次物理请求在约 71 秒后以 `Connection error` 失败，无 usage、工具或最终报告，测试没有执行。本批实际新增 7 次；未自动重试。缺失用量保守记入 91,649 tokens / $0.00468485 参考预留，累计账本为 25 次 / 470,648 保守记账 tokens / $0.01641896，未结算预留为 0；这不是完整实测 token/账单金额。原始输入、响应、请求失败记录和主会话评审均保留。不能把连接失败算作提示词退化或模型闭环通过。

主会话读取原始证据后登记一次 GLM-only 的 v8 受控补验，保持同 provider/model、生产代码和四步任务，不重跑 Kimi，不改提示词。最多再 4 次；本次用户补验请求合计最多 11 次，接续累计调用最多 29 次，**原新增参考成本 $0.05 上限不变**。为保留未知用量的全部保守记账，累计 token 预留上限设为 650k；共享请求 helper 的 600k 实际记账停止条件仍更严格。旧批次上限和账本不改写，不能扣除失败预留来腾额度。v8 仍无单请求 retry/fallback/repair，若再遇外部故障则保留未完成结论，不再扩张样本。

v8 结果：GLM 四个真实响应依次调用 read、单次双替换 edit、bash 测试和最终报告，实际 Runtime 完成。以下两条成功链每轮均有 57 项完整 native 工具，原始 read/修改 diff/最终字节及实际 TAP 均经主会话读取复核：

| 路线 | 成功链响应数 | API 已知 tokens | 参考成本 | 真实结果 |
|---|---:|---:|---:|---|
| kimi-code / kimi-for-coding（v7） | 4 | 71,287 | $0.000361015 | 一次 edit 两处替换，注释/格式精确保留；Node Exit 0 / pass 1 / fail 0；报告一致 |
| zai-coding / glm-5.3（v8） | 4 | 76,233 | $0.00382425 | 同上，未修改测试、未创建计划或子 Agent |

本次补验新增共 **11 次物理请求**（Kimi 4、GLM 首次 3、GLM 受控补验 4）。10 次有 usage 的响应共 185,246 tokens / $0.006078565 参考成本；一次连接失败未知用量仍按 91,649 tokens / $0.00468485 保守预留计入。新增保守记账共 **276,895 tokens / $0.010763415**，低于原新增 $0.05 上限；接续累计为 29 次 / 546,881 保守记账 tokens / $0.02024321，未结算预留为 0、未知 usage 仍为 1。不得把这些保守记账值写成完整实测 usage、发票金额或 token/成本改善。

两模型最终真实“读取→修改→运行测试→如实报告”覆盖缺口已关闭，批次结束，不再请求模型。生产版本仍为 `4c4c3774`，提示词、工具契约和 AMA 策略均未修改；只有 eval helper 的完整工具表选项及失败后落盘/停止边界得到回归补强。正例报告诚实性已实测，失败报告质量仅有离线保护验证；一个小型受控案例不能证明开放任务智能非劣，也没有同模型 Codex 质量结论。

后续接近 Codex 输入规模的设计应先按当前完整请求拆出各工具字节及语义义务，定位可等价去重的字段说明。保留规划/派发策略和完整核心工具，先做零网络内容等价审计及抓包，再决定是否值得提出新的有限候选；本次 E2E 通过不构成重新启用已撤回 schema/派发改动的依据。
