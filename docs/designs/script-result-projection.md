# Script 同响应结果去重

2026-10-26，基线 `a349eabb`。目标是减少后续请求中重复的工具结果，不改变 AMA、工具执行、SDK、专用角色、Coding 默认或完整持久回执。不是新的工作模式，也不是 Agent 首轮压缩。

## 范围与取舍

对比 Pi、Codex、DSH 后，发现 Script 模型内容包含 `metadata.toolCall.input`。进一步核实它可能是动态计算或 hook 改写后的唯一执行证据，不能删除。`receipt.input` 与 canonical input 还可能共享对象，最终相等不证明 hook 没有改写。保留实际参数、完整 content、diff、恢复消息、警告、分页/降级信息和图片。

本批只调整 `withScriptModelTool` 的最终模型文本，不改变 guest 工具返回、cell 执行、权限、预算、取消、tool observer、Session 日志与恢复。用户授权的验收边界是模型后续请求、guest 可用数据和完整持久回执，不是靠错误重试找回已删信息。

## 模型回执契约

- `receipts` 中每个原始 `result` 完整保留，ID 在当前 cell 内稳定唯一。
- 顶层 `value` 与某个完整 result 或 content 精确深等时，可以省略 value，给出 `value_from_receipt: {id, field: "result" | "content"}`。
- 顶层 value 是普通对象时，可仅对其直接字段做同样处理；其余字段保留，给出 `value_fields_from_receipts: {字段名: {id, field}}`。不递归替换深层对象，不把引用指向历史请求或外部资源。
- 比较和引用仅改变最终呈现，不修改原始对象。只有候选序列化文本更短才使用；不添加阈值配置、额外工具调用或模型总结器。
- 模型在同一响应内即可还原完整返回值。只有采用引用的结果携带 `value_reference_note` 就地解释；不增加首轮工具教学或无命中请求的说明成本。比较最终文本长度时计入该说明。
- 多个完全相同 result 选择首个匹配项；每个回执本身仍全部保留。独立摘要、改写过的值、错误详情不按语义相似合并。
