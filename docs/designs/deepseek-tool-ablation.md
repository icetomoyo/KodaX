# DeepSeek 反例归因与 Kimi 无干预闭环

继承 [复杂任务验证](complex-tool-entry-validation.md) 的原始不利样本。本轮只修改评测辅助代码，冻结生产代码、AMA 规划/派发策略及现有能力。

## 冻结设计

Layer 1 能验证守卫放行范围、工具兼容与 oracle，不能回答生成波动或工具表对推理的影响。先以测试驱动修复守卫，再用真实 Runtime 做零网络预演；通过后才付费。

DeepSeek 使用原反例的同一历史、源码、测试反证与用户任务，保留两个因素：旧/新 system，旧/新完整 native 工具表（57/54）。四种组合每格固定 5 次，按随机顺序分为五个区组，共 20 个单响应请求，不执行提出的工具。原有两组输入需逐字匹配历史 hash；混合组仅用于归因，不是可部署配置，也不根据混合组的 Todo 入口不一致评判能力。

先做第一组四请求 pilot，主会话盲评确认任务有效后再跑其余四组。所有组先保存匿名语义评审，再揭示因素、用量和耗时。分类区分正确双处修复、有害补丁、部分修复、合理读取、格式/服务失败；核对真实补丁和锚点，不靠工具名命中。重点观察是否破坏已经正确的 `>=`、零 TTL、finally 清理、空值及租户隔离。

如果新工具表在两种 system 下均出现一致损害，才增加工具因素解释的可信度；如果损害跨因素出现或未复现，则更支持生成波动。每格五次仍不足以证明零影响，允许保留 inconclusive，不为了得到全绿追加样本。历史三次只作背景，不与本轮混成同一批统计。供应商内部权重或路由变化无法由客户端完全排除。

Kimi 用相同多模块任务跑 **一次新鲜的、无响应重放的 embedded Runtime / AMA E2E**，自然选择工具顺序，要求一个继承模型的只读契约核对子任务。最多 24 次根及子 Agent 合计请求、60 项工具提案、10 分钟、一个子 Agent；物理请求同 provider 串行。私有 Git 基线、身份、行尾和临时目录在首次请求前准备完毕，模型运行期间不修改守卫或干预任务。若失败，保留结果，不现场修守卫再续跑。

模型须真实读取、修改、增加有效回归、运行测试并如实报告；独立六项 oracle 在工作区之外，原 README/package/basic 测试受保护。模型可自行做旧实现负向验证，真实 shell 错误由它自行处理。成功判断包括最终源码、最后修改后的实际测试、真实子任务完成及报告准确性，不能只看 Runtime success。此 E2E 是功能 smoke，不参与 prompt A/B 因果或速度排名。

守卫复用已有 shell AST，补充 CMD 分隔符的分析规范化，实际命令原样执行。已知根目录搜索、cd、管道、NUL/合并重定向、Git stash 和限定 scratch 写入有回归；越界、保护文件和只读子任务写入仍被拒绝。守卫是评测范围检查，不冒称通用 OS 沙箱，不修改产品执行语义。

## 预算与证据

- 总上限 **44 次**：DeepSeek 20（pilot 4 + 后续 16），Kimi 最多 24；不自动重试、fallback 或重放。
- 每请求输出最多 4096 token、超时 120 秒；总保守 token 上限 **2,000,000**，冻结内置单价参考上限 **USD 1**。未知 usage 按输入 UTF-8 字节、协议及输出余量保守登记并停止新派发。
- DeepSeek 使用 `deepseek/deepseek-flash`，Kimi 使用用户明确指定的 `kimi-code/kimi-for-coding`；保持既有 reasoning 设置，分别按 token-bill 内置估价与 coding-plan 名义参考记账，不冒称实际订阅账单。
- Pilot 通过后，DeepSeek 后续组与 Kimi 自然并行；每 provider 物理并发 1。账本串行持久化，调用树共享硬上限及 AbortSignal。
- 原始输入、响应、匿名评审、映射、失败与成本全存 OS Temp，保留两份独立临时镜像。先冻结来源、输入、限额与规则，再请求；本轮不增加外部模型裁判。
- 前序累计 **366 次 / 7,192,726 保守 token / USD 0.4677252228 参考 / 9 次未知 usage**，本轮另记再累计。

## 结果

首轮守卫仍重复拒绝只读子 Agent 的 `npm test`，11 次 Kimi 请求后停止，不能算无干预成功。20 次 DeepSeek 已完整保存并盲评，不重跑。已归档首轮冻结来源，再以 TDD 修正重复拒绝；产品自身的只读权限仍正常生效。

仅对受影响的 Kimi 做 v2：加入实际子任务本地测试的零网络预演，再冻结一个全新样本。首轮 31 次已关闭，v2 最多 24 次，因此本任务调用上限修订为 **55 次**；总 2,000,000 token / USD 1 参考上限不变，扣除首轮已用额度。不重放响应，不在 v2 运行途中修改守卫。

### DeepSeek 控制变量复核

五个随机区组、四种组合的 20 次响应全部保存，先由主会话盲评补丁和锚点，再揭示映射与用量。旧旧及新新输入 hash 逐字匹配历史样本。未执行单响应提案中的工具。

| system / native 工具表 | 正确双处修复 | 部分修复 | 合理补读或提议测试 | 有害补丁 |
| --- | ---: | ---: | ---: | ---: |
| 旧 / 旧（57） | 2 | 2 | 1 | 0 |
| 新 / 旧（57） | 4 | 1 | 0 | 0 |
| 旧 / 新（54） | 3 | 1 | 1 | 0 |
| 新 / 新（54） | 4 | 0 | 1 | 0 |

原先破坏已正确 `>=` 的反例 **0/20 复现**。四格内部都存在相同输入下的生成顺序波动；未见损害一致跟随精简工具表。当前更支持生成波动解释，仍不能唯一归因历史反例或证明零影响。候选 4/5、基线 2/5 的直接完整修复只是描述，不是整体智能提升；单响应中的部分修复和补读也不是全任务失败。

旧 system / 新工具表一份响应正确修复后添加了不必要的 `existing.catch(() => {})` 与未使用变量，但仍返回原 Promise，未吞掉调用者收到的拒绝。计为正确但不够精简，保留为不利质量观察。每格五次不足以估算稳定的总体成功率；不为“全绿”追加生成。历史错误补丁仍完整保留。

### Kimi 最终无干预 E2E

v2 使用全新工作区、私有 Git 基线与会话；没有响应重放、运行中修改守卫、人工续指令或恢复。真实 embedded Runtime / AMA 完成 **11 次请求（根 8 / 子 3）**、21 项工具提案，一个真实只读子 Agent 完成契约核对，主 Agent 获取并整合其报告。物理并发峰值为 1，守卫拒绝数为 0。

主 Agent 实际读取、修复三个模块、新增 12 项有效回归，在最后修改后运行 `npm test`，**13/13 通过**；工作区外独立 oracle **6/6 通过**。公开 API、原 README/package/basic 测试和原注释保留。长度前缀编码解决任意字符串 pair 碰撞；TTL 相等、零值/null、有效空值、租户隔离、同 pair 去重、失败后重试均有实际验证。模型未接触独立 oracle。

最终报告准确说明 13/13、改动范围及子任务仅做静态核对，未冒称做过压力测试或独立 oracle。保留两点措辞局限：主报告“失败路径未改动”应理解为保留 Promise 传播、只缓存成功和 finally 控制流，实际 cleanup 键有 `key→id`，报告表格也列出了该变更；子报告“旧测试全部通过”没有自己的执行证据，主 Agent 随后实际运行全部测试并明确子任务未运行测试。不能写成报告毫无瑕疵，也不据此误判功能失败。

新增评测守卫的两项表驱动回归（含 13 类拒绝输入）和 `typecheck:tests` 通过。真实 Runtime 零网络预演为根 7 / 子 2 次脚本响应，验证子 Agent 实际 `npm test`、第二次派发/子任务写入/递归派发三项拒绝及共享请求上限；没有网络调用。生产代码与 AMA 策略未变，未重跑整个产品测试套件。

### 决策与实际账本

结论为 **recommend-iterate**：支持保留现有三处重复入口收敛，本轮不扩大工具退役，不改 AMA 规划/派发或底层能力。DeepSeek 未出现随工具表稳定变化的有害信号，Kimi 补齐了此前缺失的无干预闭环；这些证据不能外推为大型仓库或长程任务的普遍智能非劣保证。
