2026-10-25。状态：**候选、离线回归、三模型受控配对及三次真实复杂任务已完成；发现效率与规划行为风险，暂不默认采用。**
接续[工具总方案](tool-portfolio-plan.md)，保留 Agent / Coding / Script、Coding 默认、AMA、SDK 和专用角色。
本轮先做一个覆盖通用工具与 Worker 教学的完整候选，不再逐个小工具反复付费验证。
具体用例、预算和证据格式见[验证案例](compact-contract-validation-cases.md)，执行结果与未验收范围见[验收记录](compact-contract-validation.md)。

## 1. 目标与非目标

在固定纯净完整 Host 场景，将 Agent 首轮模型字段估算从约 16.4k 降到 **10,000 以下**，同时保持：

- 完成任务所需的证据、修改、验证和准确报告；不能用少验证换少 token。
- 现有规划、并行派发、协作、所有权与 AMA 收尾策略；简单任务仍直接执行。
- 无新增发现步骤、参数查询、确认问题或为学习省掉的说明而发生的失败重试。
- 底层执行、权限、预算、取消、工具结果、SDK 兼容与专用角色行为。

10k 是固定场景的工程目标，不是任何项目、用户 Skills、MCP 和会话历史下的总输入上限。
不能通过裁掉项目规则、少算子调用、关闭能力绑定、删 builtin Skills 或换 tokenizer 达标。
实现目标与采用判断分开：未达到 10k 如实记未达标；低于 10k 但质量或往返有可信回退也不进入默认。
有限测试不能数学证明所有任务智能不下降；本方案提供规则可追溯、机制等价、受控行为和真实闭环四层证据。

首批不做：隐藏/删除工具、参数延迟披露、问答 schema 统一、Todo 状态模型改变、AMA 策略重写、
结果摘要/截断、自动模式选择、新路由框架、第四种模式或公开实验配置。

## 5. 实现边界与兼容方案

### 5.1 首批一个原子候选：Worker + 通用工具说明

- 在现有 registry 模型投影和普通 managed root 装配处处理；只有确认具有所需 Worker 教学的执行上下文才用紧凑工具投影。
- 工具名称、输入结构、执行函数、权限注解、顺序约束、结果格式均不变。仅工具顶层说明和参数注释可变。
- 结构相等比较必须识别 schema 的 properties：名为 `description` 的业务参数不能当注释删除；不能删 default、enum、required 等。
- 同一条协作/Todo/验证政策由 Worker 负责；具体参数、副作用、恢复入口由工具负责。必须交叉核对组合后的完整模型输入。
- 不把 SDK 原定义全局改短：普通 SDK、自定义 system、专用角色、部分工具集、宿主同名工具保持原有效契约。候选选择依据真实 managed root 身份与能力来源，不靠字符串猜测角色。
- 首批仅普通 Agent/Coding root；Script 完整可调用契约装配不同，本批保持原字节。子 Agent 及专用角色先保持原字节，仍计入全任务成本。后续扩大作用域需单独验收。
- 原行为与候选作为评测准备阶段的两份完整输入/构建，不增用户开关。默认采用前，生产路径仍用原契约。

现有实施边界：[模型投影](../../packages/coding/src/tools/model-tool-definition.ts)、
[Worker](../../packages/coding/src/agents/worker-role-prompt.ts)、
[公共执行教学](../../packages/coding/src/prompts/execution-guidance.ts)、
[现有候选测试](../../tests/first-turn-compact-candidate.ts)。不要照搬旧候选的文字范围/前提，先做 substrate 核对。

### 5.2 后续独立候选，不与首批相加报收益

- 问答单/批形状统一：只有完整覆盖 askUser / askUserMulti / input 宿主后再讨论，不先引兼容重试。
- Script 完整 TS 声明：需保留 JSON Schema 约束和必要返回类型，不预算截断，不先发现再调用。
- Script 回执去重：先证明哪些 canonical 参数副本没有新信息；完整错误/部分效果/警告和审计保留。
  选择性正文输出涉及 `scriptReadPaths`、容量恢复和证据可见性，必须另立行为实验。
- 更改并行优先/计划策略、精简 Todo 语义不在当前授权的表示优化内，不能借“SDK 保留”宣称无损。

## 7. 验收与结论边界

### 不得默认采用的明确情况

- 必要规则/参数缺失，执行权限或能力变化，用户/SDK/专用角色契约被覆盖。
- 已确认候选引起新增发现、重复读取、无效问答、重复派发/等待、未验证报告或错误收尾。
- 省掉验证或少做任务导致的低 token；预算截断/未知 usage 被按成功或零成本处理。
- 测量只统计 root、忽略子任务/辅助请求，或直接拿不同版本历史数据作因果结论。

有限样本中某一次多一轮不直接等于真实退化：先区分 scorer、预算截断、provider 波动和候选语义。
但无法解释的关键质量/往返差异不能写成“已证明不退化”；保持候选，报告剩余证据。
不强求每个 alias/case 全票相同，不将不同 provider 平均值掩盖单一 provider 的系统性回退。

最终报告必须包含：固定场景首轮成本、完整任务质量、根/子/辅助/物理调用、关键路径往返、
无效/发现/重试次数、总输入/输出/缓存 token、已知与保守费用、耗时、失败归因、采用建议和未验证范围。
“首轮 <10k”“离线等价”“有限模型无可信回退”“统计意义非劣”分别陈述，后者本轮不作保证。

## 9. 2026-10-26 修订：从整体候选改为分拆交付

### 问题与已有成果如何处理

三模式、工具装配/兼容边界、Script 执行链和已有重复入口收敛是前期实际实现，保留。完整紧凑候选新增的降幅则尚未进入默认。
最近两轮拒绝恢复修复解决的是已观察到的重复失败处理问题，不应计作 token 优化交付。

原候选同时修改 34 项工具文字、整段 Worker 教学及 Memory/manual 的规则归属，无法从完整任务反例判定是哪部分导致行为差异。

旧模型样本、真实轨迹和规则账本仍有价值，复用来设计针对性验收；不把已投入验证量当作产品收益。

### 当前策略到底是什么

现有默认先按 Agent/Coding/Script 选择工作面，并沿用实际宿主绑定、权限和能力条件装配。
Agent 不装配 Coding 的 18 项 Repo/LSP 专项入口；普通 root、SDK、自定义宿主和专用角色不能混同。
Script 首轮仍提供完整可调用契约，以避免先发现再学习参数；它是程序化调用方式，不是低 token 模式。

未采用的紧凑候选不删工具、不隐藏参数、不增加发现：只缩短工具说明/参数注释，并重写 system 教学、去除跨处重复。
因此必须将“表示相同能力”与“模型按相同方式工作”分开验收。当前可证明前者的一部分，不能声称后者已成立。

### 第一步：独立落地工具契约表示，保持行为教学原文

1. 保留当前完整 Worker（含新恢复原则），不使用原候选的 Worker 重写，也不移动 Memory/manual 的 system 规则。
2. 将工具文字投影作为一个完整批次审计：工具用途、参数约束、返回值/副作用、权限和恢复信息都必须仍可见。
   删重复参数解释、缩短冗长表述；凡依赖“先重写 Worker 才能成立”的项保持原文，不以全批达标为由强行压缩。
3. 复用既有模型投影/装配边界，SDK、宿主覆盖和专用角色继续拿到各自完整有效契约。不引公开开关或新的动态路由。
4. 复用 schema、装配和真实执行离线用例；用有限配对针对协作参数、Todo/问答和失败恢复的决策验证整个批次，
   不逐工具发模型请求，不重跑旧 P01–P08/C01–C02 全矩阵。具体 paid 输入和调用上限需在实现后的独立 revision 预注册。
5. 通过后进入生产默认装配，验证实际发布产物并交付新默认抓包。未达 10k 也交付已确认的降幅，不再等待最终目标一起采用。

第一步验收关注新默认的独立收益；13.7k 是全部工具候选成立时的估算，不是必须拿到的保底。

### 第二步：行为教学只做规则归属去重，不再整体改写

保留原有触发条件、时序、例外和恢复条件的文字，逐条说明重复出现在哪里、保留在哪里、哪些消费者仍能看到。
首先检查 Worker / 协作 / Todo 的跨处重复，以及 Memory/manual 已由工具精确说明的操作细节；
对只在一个地方出现的行为要求不删除。不能将重复规则迁到需要额外调用的 Skill 或工具发现入口。
稳定教学、动态 Actor/计划事实和用户项目指令分开记账；不能将必要的当前状态当重复文字删除。

只验证此独立增量对旧反例和有界完整任务的影响。第一步已通过的改动不因第二步失败一起撤回。
若剩余 3.7k 无法在这些条件下删去，应报告可达值；涉及能力可选化或改变 AMA 的方案单独讨论，不能偷偷用权限或隐藏菜单凑数。

### 停止无效验证，明确交付定义
