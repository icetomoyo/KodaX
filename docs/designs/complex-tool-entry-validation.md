# 复杂任务验证：工具入口收敛

验证对象仅限 `tool-entry-consolidation.md` 中的三个重复入口收敛。冻结当前产品代码，保持 AMA 规划、派发、底层能力不变；本轮不继续退役工具。

## 任务与判据

使用无外部依赖的多模块缓存客户端，修复租户身份碰撞、TTL 边界、跨租户并发隔离和失败后重试。旧测试故意存在缺口，模型须自行增加回归；独立六项测试放在模型工作区之外。保护原测试、README 和包配置，保留公开 API、有效空值与同租户请求合并。

这是小仓库中的中等复杂任务，覆盖跨文件推理、反证修复和真实协作；不能外推为大型仓库、长上下文压缩或多层代理的普遍能力保证。

离线先验证原实现通过旧测试但不能通过独立验收，参考修复通过六项独立测试。真实 Runtime 的零网络脚本另验证读、改、测试、子 Agent、共享请求上限及隔离拒绝。离线不能回答模型是否理解替代入口、正确选择修复及如实整合证据，因此增加有限真实请求。

## 冻结与预算

- 基线为归档的 HEAD `5ada4f7c`；候选为本工作树。实际 Runtime 捕获的 native 工具表为 57 / 54，使用相同 Windows 目录、用户任务与历史内容，只规范化随机会话标识、时间与 provider 忽略的消息元数据。
- 三个固定单响应检查点：陌生多文件任务起步、外部变更后读取完整 Todo 详情、根据真实失败测试提出两处最小修复。每个检查点四路模型、两个版本，共 24 次请求；不执行这些响应提出的工具。
- 模型为 `zai-coding/glm-5.3-flash`、`zai-coding/glm-5.3`、`deepseek/deepseek-flash`、`kimi-code/kimi-for-coding`。先跑 Flash/Kimi 的前两个检查点共 8 次，主会话盲评后才补齐余下 16 次。先保存语义评审，再揭示版本、token 与耗时；工具名称使盲化不完全。
- 候选单独跑 Flash、Kimi 各一次自主 E2E smoke，不做自由循环 A/B 因果比较。模型自行安排读取、规划、编辑、测试、修复与汇报；明确要求一个只读兼容检查子 Agent，整合其结论。每次最多 20 个根及子 Agent 合计请求、40 个工具提案、8 分钟；共享串行队列，最多一个继承模型的只读子 Agent，不允许递归和独立 Workflow 执行器。
- 总上限 72 次物理尝试（24 检查点 + 40 smoke 上限 + 8 次仅针对可信差异的配对复核预留），保守计量 3,000,000 token、名义 USD 3。每请求输出上限 4096、超时 120 秒、单次物理尝试、无自动重试与 fallback。两个 ZAI 模型共用串行通道。未知 usage 按输入 UTF-8 字节加输出及协议余量保守计费，停止派发待审。
- E2E 使用真实 embedded Runtime / AMA / 工具执行；仅隔离任务外的事后 learning review，防止产生未计量后台请求。SDK 的 `maxIter` 不作为整树硬预算；在共享 provider 边界对每次根与子请求计数并传播 AbortSignal。默认 Actor 槽位不改，实验边界在工具提案执行前限制一个子 Agent。
- 文件与 shell 范围限制属于实验隔离；合理策略被隔离拒绝时标记实验限制，不能据此声称智能下降。预算耗尽标记截断；provider 错误独立列出。正常中间读取、规划不因单响应截止而判失败。

输入、来源及辅助脚本的哈希、路由/价格、盲化映射、评审规则和预算在调用前冻结。原始请求、响应、工具事件、工作区与账本保存在 OS 临时目录，并保留两份独立临时备份；不提交密钥或 raw。前序累计 302 次请求、5,893,476 保守 token、USD 0.4072162096 名义参考、8 次历史未知 usage；本轮另记并汇总。

## 验收与决策

配对评审观察证据质量、完整详情读取、实际补丁锚点、两处修复语义、额外工作和虚构完成；不使用工具名命中替代语义评审。E2E 核实模型真实读改测、在最后修改后实际运行测试、独立六项验收、原文件保护、子 Agent 实际完成及最终报告是否符合可见证据。保留每项局限，不以全部通过推导普遍不退步。若出现可信候选劣化，只复核受影响检查点并分析原因，再决定是否保留改动。

## 结果

结论：**recommend-iterate**。本轮不继续扩大工具退役，也不能据此宣称普遍智能非劣。替代入口理解和部分复杂修复得到支持；DeepSeek 的真实不利样本尚未解释，Kimi 的实验恢复过程也限制了结论。

### 固定检查点与反例

24 次原定请求中，候选 Flash 起步请求因 Node 未启用已有环境代理而连接超时；保留并保守计费，没有重试。因此为 11 个完整配对和 1 个单侧结果。纠正连接环境后才继续未执行的请求。主会话先保存语义评审，再揭示版本与 usage。

| 维度 | 观察 |
| --- | --- |
| 陌生多文件任务 | Kimi、GLM 5.3 两版均读取契约、三个模块和旧测试；DeepSeek 候选读六项，基线先读 README/package，两者均属合理起步，单轮不能推断后续完整性。Flash 候选因上述超时缺失。 |
| 外部变更后的完整 Todo | 四模型都能从 get 切换到 list(id)，不重建计划或提前验收；Kimi 候选额外读取一个相关 Todo，未见实质损害。 |
| 反证修复 | Flash、GLM 5.3、Kimi 两版均提出正确的零 TTL 与 in-flight 清理补丁，锚点有效，没有声称已执行验证。 |
| DeepSeek 窄复核 | 两次额外配对共 4 请求后，共有每版三份响应：候选两次正确，一次把已正确的 `>=` 改成 `>`；基线两次正确，一次先读取旧测试。后者属于中间步骤，不算错误补丁。候选错误会破坏到期相等与零 TTL，必须保留。 |

DeepSeek 的错误是样本层面的实际损害，三次配对不足以确定为入口收敛引起。冻结历史、源码和测试反证逐字相同；系统说明唯一差异是 Todo 同步读取入口名，未删除 TTL 或推理规则。不能把未知归因为“肯定是噪声”，也不能由单个样本断言总体退化。后续应先复用该反例，隔离工具表与同步说明的影响，再决定默认推广；不添加针对单个模型的迎合提示。

同场景起步的已知 API 输入：Kimi 16,188→15,872（-316），GLM 5.3 17,558→17,208（-350），DeepSeek 18,139→17,783（-356），约省 2%。Flash 的缺失侧不估填。输出长度、额外读取与后续轮数可抵消输入节省，不能把这个比例当成全任务收益。

### 实际 Runtime 闭环

| 模型任务 | 唯一付费响应（根/子） | 总 usage token | 实际测试及独立验收 | 证据性质 |
| --- | ---: | ---: | --- | --- |
| GLM 5.3 Flash，修正实验后的样本 | 9（7/2） | 167,667 | 原测试 + 新增 11 项，12/12；独立 6/6 | 实际 read、三模块 edit、write 回归、npm test、wait 与报告。完成一个真实只读子任务并整合结论。 |
| Kimi，同一任务的各恢复段去重 | 18（15/3） | 406,373 | 最终 12/12；独立 6/6 | **恢复辅助下通过**。真实请求生成的决策、实际读改测和报告完整，但不能称无干预自主通过。 |

两者公开 API、原测试、README、package.json 和原注释保留。主会话核实最后一次恢复/修改后确实重新执行测试，最终报告对应真实输出，没有冒称执行独立 oracle。Kimi 还主动在旧实现上验证新测试能失败，识别 CMD 分号拼接未恢复 stash，实际恢复后重试验证。负向测试精确结果为 3 failed、4 cancelled、4 passed；报告先称“7 个失败”后解释级联取消，有计数措辞不够精确的问题，不能写成七个独立缺陷。

Flash 首份样本被实验守卫误拦 `2>&1`，记为 eval-invalid，保留 9 次请求、150,910 token，仅重跑受影响样本。Kimi 的合法根目录 glob、工作目录 cd、NUL 重定向、Git stash 负向验证和产品提示允许的临时文件输出也被守卫误拦；这些是**评测设计缺陷**。逐次保存原因、源码哈希和现场，再恢复原夹具并重放已保存的模型决策，不重复生成或计费。恢复段依次重放 3、8、9、10、13 个响应，全部有 replayOf 链与零物理请求标记；唯一付费请求仍只有 18 次。私有 Git 的初始 HEAD/身份在恢复时补齐，原/中间工作区与 stash 状态留有快照。

因此，本轮只能确认 Kimi 在这些干预后完成了闭环，不能将其计作一次无干预成功，也不能用自由执行路径做 A/B 胜率或速度比较。Flash 与 Kimi 的模型请求耗时合计分别约 104.1 / 154.1 秒，排除了人工审查、停顿与本地重放，**不是端到端墙钟时间或性能排名**。独立任务先后执行也不能代表 panel 的并发吞吐。后续若需要发布门槛，应先修整评测执行层，再补小样本无干预证据。

### 可复用回归与账本

持久化夹具、三个检查点和六项独立 oracle 位于 [benchmark/datasets/tool-entry-complex](../../benchmark/datasets/tool-entry-complex/fixture.ts)。付费调用结束时 17 项冻结来源全部未变；随后只补充 oracle 对“正确修复后又把 `>=` 改回 `>`”的确定性拒绝断言，并写入本结果。夹具测试及测试类型检查通过，生产代码保持冻结；没有重跑整个产品测试套件。

本轮共 **64 次唯一物理请求**（24 原定检查点 + 4 窄复核 + 18 Flash 含无效样本 + 18 Kimi），无自动请求重试或 fallback。63 次有 usage，1 次连接失败未知，按输入字节及余量保守登记；合计 **1,299,250 保守 token**。冻结单价参考总额 **USD 0.0605090132**，其中 DeepSeek 按内置 token-bill 单价估算 USD 0.0068188232；其余为 coding-plan 名义参考，不能冒称订阅增量账单。累计 **366 次 / 7,192,726 保守 token / USD 0.4677252228 参考 / 9 次历史及本轮未知 usage**。

原始输入、响应、盲评、恢复审查、全部辅助脚本版本、工作区快照和账本留在 OS Temp 的 `complex-tool-entry-20261018-1024`，另有两份独立临时副本。账本按物理请求去重，重放不二次计费。实验问题、负向测试和不利模型输出均未删除。

后续完成 [DeepSeek 控制变量与 Kimi 无干预复核](deepseek-tool-ablation.md)：2×2 五区组的 20 个响应未复现有害补丁，未见损害一致跟随工具表；新鲜 Kimi Runtime 无干预完成 11 请求，实际测试 13/13、独立验收 6/6。该证据补齐此前缺口，不能改写本页历史样本为无干预成功，也不能证明普遍非劣。建议保留已做三入口收敛，本轮不扩大退役；最新累计账本见复核记录。
