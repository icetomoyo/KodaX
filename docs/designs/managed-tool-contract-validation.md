- 普通生产 managed root 的 Agent/Coding 请求缩短 32 项工具文字。保留 spawn_agent、todo_create、todo_list、todo_update、wait_agent 的顶层行为说明，仅精简其参数注释。

- undo 的原文已经足够短，不纳入投影。没有删工具、隐藏参数、替换 handler、引入发现请求或新公开开关。
- SDK 原生定义/独立 Agent 工厂、子 Actor、专用角色、定制系统说明、可见性策略、Script 包装均不继承资格。通过公开 runManagedTask 调用普通生产根流程时，其呈现遵循同一生产规则。

- 工具集合、schema 中类型/必填/枚举/默认值、业务字段 description、权限/预算/取消及恢复执行链保持原样。只改模型收到的说明文字。

## 有限模型验证与停止条件

不能靠离线证明模型理解更短文字后仍作同样决定。因此只比较工具文字，冻结同一完整 Worker 和相同历史。
使用 GLM 5.3、Kimi for coding、DeepSeek Flash；三个关键检查点、两臂各一次，总上限 18 次。
先 GLM/Kimi 两场景共 8 次，主会话盲评后才继续其余 10 次；每格最多一次，不因输出不理想重跑。
场景覆盖只读并行派发/所有权、已知 Todo 与交互契约、编辑失败后的合法恢复。单次决策的诊断不得冒充完整自由任务成本或统计非劣证明。
输出上限 8,192 token/次、180 秒/次，全实验 700k token 与 $1.5 保守费用上限；未知 usage 不能记零。raw 与冻结输入仅写 OS Temp。

实际完成 **18/18 次单次请求、每格一次，0 重试、0 provider 错误、0 usage 未知**。先盲评再揭盲，未执行模型选择的工具。

这些是 **L2 独立检查点总和，不是全任务 token 或墙钟时间**。串行/并行执行、缓存和延迟波动使小样本耗时不能用于宣称加速。
Kimi 原版问答只执行多余 todo_list，候选直接提问但默认值有误；不能把一方未完成提问记为正确，也不能忽略候选参数错误。
DeepSeek 双方都没有立即派发，双方问答都不完整，不算整场干净通过。三模型六个恢复响应均先读精确目标，没有重试禁止清理、换写法绕过、全文件重写或发现调用。

决策为有限范围的 `recommend-ship`：恢复 ask_user_question 的**全部**原契约，交付其余 32 项；不引入默认值自动修正、额外确认或 provider 特例。
最终 32 项只重新做必要的离线和发布验证，**没有再次跑模型**。上述 18 次严格标为 33 项候选证据，不能冒充最终版本完整真实 E2E，更不能证明所有复杂任务的质量/往返非劣。
此前真实复杂 E2E 只作为历史失败边界，亦不挪作这次最终版本验证。剩余问答可靠性与派发前侦察问题记录为未闭合，不在本批扩展修复或反复烧模型。
