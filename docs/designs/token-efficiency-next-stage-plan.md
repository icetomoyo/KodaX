## 1. 目标与不变项

- 保持任务质量与报告准确性，在完整任务往返基本持平的情况下，降低首轮与全任务 token；同时观察费用、耗时。
- Agent <10K 保留为目标，**当前没有已经证明可无损削掉约2K的候选**。不拿子 Agent、缓存或 Script 收益冒充根 Agent 首轮收益。
- 保持 Coding 默认、Agent/Coding/Script 单入口切换、AMA 规划/派发、有效子审查、SDK、专用角色与底层能力。
- 不强制工具发现、不增加固定前置步骤、不为通过反复重跑、不对案例写特化教学。
- 不把每个样本零增轮作为采用条件；也不以缓存更便宜掩盖明显的历史增长、质量下降或固定额外调用。

## 3. 按收益对象拆分，而不是只排一张工具删减表

| 路线 | 主要收益对象 | 最小工作 | 风险及推进条件 |
|---|---|---|---|
| A. 根共享契约与实际装配 | 根三模式首轮、每次输入 | 按规则归属与工具家族一次性审计，共享规则只教一次，明确未绑定能力不注入 | 不删除模型做决策仍需的信息；不足以形成有规模净收益就停止改词，不凑10K |
| B. 内置通用子 Agent 契约 | 子首轮及协作任务 | 子system与工具说明成对精简，复用规范定义与既有装配 | 历史约1.7K是毛潜力；须扣新增子system规则。先不改专用角色/宿主override |
| C. 工具回执 | 全模式、多轮历史驻留 | 去确定重复的路径标题，再比较单处精确替换的短确认 | 保留错误、归一化/多处替换、并发警告、诊断与恢复证据；不能诱发额外read |
| D. 缓存与动态上下文 | 未缓存输入、费用、预填延迟 | 完成保留机制边界，使用生产affinity配置测跨Session | 不保证服务端命中；旧上下文不升格为当前权限；总历史体积单独计 |
| E. Script完整契约表示 | Script首轮、参数理解 | 比较当前嵌入JSON Schema与等义紧凑声明，参数首轮完整可见 | 不加发现步骤，不改执行/校验/预算；不建新schema语言或第二执行器 |
| F. 长会话与恢复 | 全任务、压缩调用与重读 | 先测信封累积、重复输出、摘要和恢复开销 | 不默认开启microcompaction，不直接交换裁剪/摘要顺序 |

### A：根与工具全局审计的交付要求

重新冻结一次装配；对 system、动态信封、工具顶层描述、参数说明、schema结构、Skill目录、Script叶契约分别计量。
全部工具按文件/执行、计划/协作/交互、Goal/Memory、Web/MCP/Skill、RepoIntel/LSP、视觉/恢复分族登记：
实际入口、直接可用性、规范契约、规则归属、既有替代、SDK/专用角色差异。复用
[工具模式分配](tool-mode-allocation.md)，不再逐工具重新询问用户。

审计输出必须区分：必需决策规则、执行器已强制且无需重复解释的内部细节、确定重复、使用条件不满足、历史不再适用。
“执行器会拒绝”不等于可以删除指导模型避免无效调用的说明。MCP未绑定与尚未连接、LSP关闭与懒启动、无Goal状态与无Goal能力不可混淆。
普通Agent仍不默认装Coding的Repo/LSP工作面，Coding保留对应能力；四项Repo工具不能仅凭名称相近并入relationship_scan。
不因Pi缺少某工具就删除，也不因KodaX已有引用就认定必须常驻。参数约束与兼容API不靠删schema凑数。

builtin Skills先区分目录与激活全文。目录只改确定重复或过期措辞；技能触发准确性有价值，不能为约百token牺牲它。
视觉工具先与当前视觉合同一起做完整自足说明复核。暂不增加“先tool_search才能正确用”的固定步骤，也不按关键词自动猜视觉任务。

### B/C/E：表示层候选的共同约束

- 每个候选保留独立差异与结果；Agent/Coding/Script共享的规则同步处理，执行边界不混同。
- 子契约沿用root/child身份、只读、递归共享预算、取消、消息与最终交付规则。不给SDK override静默套用根投影。
- 编辑回执先证明现有UI/SDK/持久化载荷能保留完整证据；当前不能假定已有无成本双视图。
  若需要新造整套输出协议，收缩为可用现有投影实现的范围。错误回执不与成功回执一起简化。
- Script现代码将完整schema放进description，再经外层JSON序列化，存在表示成本研究价值；
  对嵌套对象、枚举、可选/必填、默认行为、数字限制与特殊语义完整对照，节省必须包含新增说明。
  原生控制工具、undo、部分失败回执和叶调用执行链不动。不能表达的契约保留原表示；无明显收益不推进。

## 5. 验证设计

执行遵循 [EVAL_GUIDELINES](../../benchmark/EVAL_GUIDELINES.md)。先离线；机制问题不花钱问模型。

### 离线与固定轨迹

| 场景 | 要证明什么 |
|---|---|
| 三模式真实SDK序列化、根/通用读写子/专用角色/override | 该精简的契约成对精简，其他路径不变；native、发现、桥接、Script权限一致 |
| 连续2/5/10个用户Run、同轨迹20/50次模型请求 | 首处分叉、历史驻留、累计模型输入、压缩触发是否增长；合成回放只证明机制，不证明模型会选同一轨迹 |
| 更新/撤销Skills、MCP与能力；超长信封；用户纠正 | 最新事实有效，撤销不因截断永久丢失，旧任务指引不覆盖新任务 |
| Runtime重开/fork、压缩、权限收紧、取消 | 安全重建、公共SDK历史、恢复证据与实时权限不退化 |
| 精确/归一化/多处编辑、并发警告、长输出分页 | 修改结果与重要回执完整；短确认不丢实际变化，不伪称验证完成 |
| 父子孙、无根usage、目标切换、父Run结束 | 已知调用恰好记一次；不丢/不重计/不串目标；不靠增加模型回合结算 |
| Script多个cell与叶错误/取消 | 参数理解表面完整，权限/预算/部分效果/undo边界不变 |
| 实际npm包及Windows产物 | 使用打包后的同一装配，模式切换与恢复有效；macOS/Linux未实测须明确 |

### 有限模型验证

- 目标池沿用用户指定：`zhipu-coding/glm-5.3`、`kimi-code/kimi-for-coding`、`deepseek/deepseek-flash`。
  不用zai替代，不默换gateway；历史数据原样保存。
- 每个行为候选先2个有区分度的固定检查点×2臂×2家×1次，8次pilot。
  实验有效后补第三家，并按需要扩到每臂2次，单候选上限24次；有分歧先读raw，不循环加样本。
- 初批最多两个行为候选；Script若也需付费验证，进入下一批，不能暗中扩大初批。
- 固定检查点至少包括：精确编辑后继续验证；归一化/并发警告必须处理；只读子审查拒绝后合法继续；
  合并子审查证据并如实报告。采用与候选相关的两项，不把全部场景笛卡尔积。
- 最终组合最多3类自然任务smoke：连续修复与追问、只读子审查与恢复、Script批量编辑与输出恢复。
  三家覆盖受影响行为；完整执行计root/child/aux总调用，不以只有root的数字隐藏子开销。
  全任务质量/token/耗时都报告，但不把自由轨迹单次差异当prompt因果证据。不同模式或模型结果不能直接当配对。
- 每次实验另冻结精确输入、raw路径、源码hash、全部物理调用上限、输入/输出token、费用/套餐依据及timeout。
  本计划不是未设上限的付费授权；pilot预算按实测输入估算。失败、超限、未知用量保留，不为了通过重跑。

原始版同案例只用一次留存；不存在可比留存就明确缺口，不将R16基线改名为原始版。
固定输入对照、完整任务轨迹、跨产品能力对标分开呈现。原版缺陷和共同模型失败不自动否决结构性收益。
模型比较由主会话先盲评再揭盲；规则覆盖和机械oracle不能代替报告准确性、真实测试与任务价值判断。

## 6. 常驻观测与采用条件

复用抓包/验收工具，不建新生产监控平台。记录：

1. 首轮完整模型字段估算：root三模式与child单列；字符、字节、估算token不混用。
2. 完整任务输入/输出、cache read/write、未缓存输入、root/child/aux物理请求、用户Run数和耗时。
3. 命中率为当前cacheRead/当前input；R16的cacheRead/上次input是覆盖指标，可超过100%，不能叫命中率。
4. `/goal`净token、全任务token、参考费用、真实套餐消耗分列；缺失usage不是0。
5. 字节变化预算与首处分叉诊断：允许说明充分的新能力增长，不让测试强迫删除有效规则。

采用：独立规则/权限/恢复回归通过，有可复核净收益，未发现可信候选独有质量回退或固定额外调用。
低样本模型结果如实标置信度；不要求所有样本全绿，也不把“没检出差异”宣称统计等价。
拒绝/暂缓：收益只有描述字符而整请求不降；需额外发现或重复读取；丢失证据/权限/角色合同；
把缓存改善与新增历史的代价混算；必须新建复杂平台才能取得小收益。
最终报告每项明确已采用、未采用及原因、已完成验证、尚未覆盖，不用下一轮实验无限延后结论。

## 8. 渐进披露的追加讨论（本批冻结实验之外）

用户侧聊要求把“像Skills一样按需披露不常用工具”纳入整体。主线核对源码后，两个子Agent再次交叉讨论，
没有修改本批已冻结模型输入，也没有追加付费矩阵。

已确认：KodaX `tool-resolution.ts` 保留完整参数schema、仅替换description；`tool-search.ts` 又返回完整description+schema。
因此它目前主要是教学延迟，不等同于完整schema延迟；发现不是执行器强制前置，却可能被hint教学成必经步骤。
AMA菜单一次装配仍为短说明，动态substrate按unlock恢复长说明；unlock的WeakMap不能据此宣称跨Run永久保存。

Pi `extensions/tool-search/tool.ts` 搜索后激活工具，下个模型调用携带schema；结果返回名称/说明。
Codex `tool_search_spec.rs` 明确搜索延迟工具并在下一调用暴露。两者愿意承担有价值的首次发现成本；
DSH Native/PTC核心链仍直接列schema/内联完整SDK，不把PTC或Minimal当成免费schema延迟。

| 方案 | 决策 | 最小验证与停止条件 |
|---|---|---|
| A 现状 | 冻结对照 | 同时计菜单schema、发现回执副本、是否多一次发现 |
| B 常驻schema+自足短说明，详细教学可选 | **下一批优先候选** | 逐工具核对短说明足以正确直接调用，权限/参数/错误恢复不变；不能只删tool_search字样就声称自足 |
| C 单个大而低频外部namespace按需schema | 独立研究候选，不默认推广 | 不用、首用、中途用、频用、发现失败恢复五轨迹；承认首次发现轮，计算动态菜单的缓存失效与全任务成本。频用明显亏损/恢复退化则不默认 |
| D 显式Skill/模式选择后宿主预装 | 先审计现有装配 | 在首次请求前装配关联工具，保留registry/scope权限；不加分类模型、不按关键词猜权限 |

先复用已脱敏的留存，按逻辑tool-call ID去重，核实工具族大小、使用率和首次使用位置；确切可复用日志路径尚未取得，

## 13. 历史版本自失效修复与缓存归因（2026-10-31）

### 13.1 最小版本契约

已确认的缺陷是正常 search 回执及后续 tool call 本身会追加历史，使整个 lineage 的 revision 改变。
模型照搬 search 或 stale 返回的全局 revision 会再次 stale；不能用忽略调用参数来绕过。
新增可选 `entryRevision`，复用原 `revision` 输入，以 `entry:sha256:` 区分目标证据版本。
它绑定条目 ID、父节点、物理/逻辑来源、时间、角色、消息来源以及公开可读证据，普通尾部追加不使其失效。
目标变化仍拒绝并返回新版本供明确的新读取；移除、隐藏、fork/rewind 及子 Session 边界继续生效。
旧顶层全局 revision、哈希算法和严格比较保持兼容，SDK transcript page/chunk 继续用原快照版本。
详见 [历史读取契约](../DD.md)；模型原生、短桥接、Script 与紧凑根说明同步教学，不新增参数或固定发现步骤。
