## 下一步先做什么

下一片是一个**最小融合候选**，不是完整框架重写。本轮只形成下面计划，未执行生产改动或追加付费验证。

| 工作 | 最小交付 | 验证与停止依据 |
| --- | --- | --- |
| 让取证入口可被正确使用 | 复用真实observation索引与文件读取；明确文件名/简称不能充当observationId。文件尚未接纳时走既有read/接纳路径，已有观察使用实际返回的ID | 先用本次无效inspect做离线反例，确认拒绝语义保持；验证目录里能找到的ID确实可用。禁止把未知ID静默映射到同名文件 |
| 关键断言与图对应 | 用已有question/label和短任务方法表达“要核实的断言—对应时间/区域—实际状态”；只对影响答案的未决点追加原帧或局部，不强制每帧/每题inspect | 回放区分“已解码/有路径”“实际送图”“被引用的事实”。能接受诚实区间，不接受把未读样本写成已核对 |
| 原帧与联系表分工 | 联系表定位后，必要时读取少量原帧；先复用现有decoder/read/inspect能力，不先新增通用视频框架 | 目标是选对并消费证据，不强制工具品牌；引用路径存在不等于模型看过。保留原PNG精度与JPEG派生限制 |
| 最小方法进入产品任务上下文 | 复用现有prompt section/capability context，把行为方法放在任务可见处，工具保留操作与限制；避免任务级和工具级重复叠加整段方法 | TDD覆盖有新图、只问历史、压缩恢复、任务结束转普通代码及仅有无关图的克制情形；核对实际生产wire，不能只测字符串模板 |

先完成可离线确认的输入/工具/来源衔接及回放，避免再花模型token证明机制是否接通。只有最小候选固定后，才考虑一个独立持出视频任务的受控确认；同一原题已多次用于诊断，不继续调词重跑直至胜出。若暂时只复验原视频，必须标为已知题回归，不能宣称泛化。局部和历史沿用已有结果，本轮不重跑；新增模型或样本另行冻结，不自动扩panel。

## 完整融合应该包含什么

“完整”应指下列闭环能一起工作，不是所有视觉任务永远加载更多工具和图片。

| 层次 | 应保留/补齐的合同 | 工程边界 |
| --- | --- | --- |
| 原件与生命周期 | 不可变原件、真实观察身份、历史回查、fork/压缩恢复、容量与失败显式结算 | 保留P0–P6已实现范围及补修；未验steer崩溃回放、子Actor owner、更多宿主仍单列，不因新smoke升级 |
| 任务方法 | 未决点→选择足够证据→核对→修订→停止；静态、历史、动态共用简短原则 | 按当前任务装配，owner存在不等于每个任务需要视觉；不引入新的规划模型、强制每轮取证或大量日志文件 |
| 证据入口 | 局部区域、历史时刻和视频源帧都有可回查的真实引用；状态/时间与图绑定 | 复用Agent媒体owner。Coding/Host负责来源事实及适配；不能把普通文件路径冒充观察身份，也不反向依赖REPL |
| 视频时序适配 | 来源视频身份、帧序号、解码PTS、尺寸/hash及采样覆盖可核对；模型能选择相邻样本并读到原图 | 先固定一个实际宿主/解码接缝，优先复用现有字段与回图合同；新增字段/API必须由该场景证明需要，不提前造通用播放器或环境层 |
| 动态反馈 | 目的、合法动作依据、实际反馈与必要的重新观察 | 沿用current/version/generation/unknown与收据后复查，旧观察不得派发；没有需求时不扩ARC/完整桌面 |
| 上下文与成本 | 原件归档后仍可回取；证据摘要保留结论及未决项，图片重发可度量 | 外部存图不自动省token。不要直接删除历史图片；保留引用、恢复/容量/错误合同，单独验证图片保留策略是否降低全程成本 |

现有严格8-bit PNG派生/像素合同继续保留。JPEG可通过原有读取路径观察，不以静默转码或精度降级来掩盖不支持的派生能力。没有证据时不新建配置、ID别名层或复杂任务状态机。

## 分片顺序与验证

1. **证据衔接和最小方法**：先修正ID使用路径、任务指导接缝和关键证据回读，TDD及实际wire离线验证。一次只改变必要链条，不同时删工具、换模型和改图片淘汰策略。
2. **确认任务价值**：使用固定最小候选，在一个持出小任务上观察自主取证、答案质量、错误纠正/诚实未核实和无用调用。主会话先评质量再揭示成本；单样本只支持下一步方向。
3. **成本优化**：有可复现质量收益后，再分别研究减少重复图片、任务级合同装配和冗余往返。保留同质量对照；更短但遗漏步骤的结果记为失败成本。
4. **必要来源适配**：只有具体使用场景需要时补原生视频来源、更多宿主或动态消费者。每片保留恢复、容量、取消、错误ID/损坏原件、过期动作及未完成反例，双轴评审后再判断采用。

每片的完整任务账目都包含输入/历史建立、压缩、主调用、取证、失败与正常辅助结算；主任务、后台、实验总开销分列。cache token计入input，美元账单另列。现有已知失败不因评分方式变化而重烧generation。

## 采用决策

- 恢复等关键事实更准确、其他任务要求不退步，且代价合理：保留这部分最小机制，按需要启用并复验。
- 有明确质量收益但更贵：先说明具体收益及全程代价，再优化；不因token单项增加直接否决。
- 质量无改善或仍错、成本更高：停止扩能力，定位证据入口、方法遵循或撤回无益指导；不以“用了visual工具”验收。
- 底层所有权/恢复/安全合同与模型收益分别评价：前者有机械证据不等于后者有效，后者某次失败也不自动证明所有底层能力应删除。

当前仍为 `recommend-iterate`，没有完整融合上线建议。本轮仅新增计划、视频结果和整理成本证据；旧设计、失败、支持矩阵及Claude并发改动保留。
