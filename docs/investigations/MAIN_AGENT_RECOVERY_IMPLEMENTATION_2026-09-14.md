# 主 Agent 文字诊断恢复：实施约定

依据：用户批准的五步计划、TEXT_RECOVERY_PROBE_2026-09-14.md，以及当前图片修复。
不用 sidecar；不执行模型生成的 shell；不改正常图片、原始消息或用户文件。

第一片公共验证边界：runKodaX 与 runManagedTaskViaRunner，Provider 替身注入明确的请求 400。
失败后进入同一 Provider 的纯文字诊断请求，再在原循环内继续；正式回答不能包含诊断 JSON。
还通过真实原生 Provider 序列化验证上游索引与实际图片负载对应，避免把 wire 索引当历史索引。

在已有恢复协调器选择 manual_continue、且现有请求预算仍可容纳诊断和继续时触发。
请求上下文错误以外的取消、权限/认证/额度、传输不可用继续走原路径；不能靠重复调用同一坏
Provider 来修凭据或服务。每个运行最多一次诊断恢复，诊断失败及修复重试失败立即停止。
图片错误证据不足时本地检查已发送图片快照，只读且不使用模型给出的任意路径。
有确切坏图/上游定位才允许省略对应请求附件；工具历史修复复用既有 normalizer，保留执行结果。
诊断可返回明确停止原因，不能为追求成功删除无关内容或改变用户要求。

上下文只在错误发生后构造并脱敏；图片/不透明思考/原生工具序列转成文字记录。
诊断使用当前模型输出预算、现有超时和凭据作用域；诊断 token 计入成本，事件复用 provider.recovery。
诊断前后检查取消和待处理输入，拒绝将旧方案应用到新输入。请求补丁只存在于本次运行的请求视图。

验收：正常路径无诊断请求；SA/AMA 自动继续；真实参数定位不混淆；无定位坏图只读检查；
错误附件/无效方案/诊断错误/重试失败/新输入/取消止损；正常图与历史不丢；四 Provider 有界验证。
最终完整复核两工作区全部 dirty diff、运行适用全量测试/类型检查/构建，并记录环境验收边界。

## 已完成实现与边界

SA 和 AMA 接入同一个共享文字诊断模块，无 sidecar、后台 Agent 或新配置。
正常路径直接返回原请求，不新增诊断请求或历史解码。入口图像校验仍按 Codex 对照后的
接收/恢复时机执行。MCP 的修改是处理 KodaX 收到的图片项，不是限制 MCP 服务端能力。

诊断不携带原生图片/工具历史/不透明思考块；只允许三个既有能力范围内的建议：省略确切
无效附件、无损工具历史整理、针对明确思考错误的清理，或停止并说明。工具整理若会删除
已完成结果或执行状态不明的调用记录，拒绝应用。原始历史和文件不改写。文字诊断也可能
失败，因此这不是保证所有错误恢复的通用故障修复器。

精确图片证据来自上游错误中的实际序列化位置，绑定本次已发送字节摘要；歧义/无效索引
不采用。凭据脱敏克隆错误时继承该证据，摘要不成为可序列化错误字段。没有精确索引的
图错才只读检查已发送快照，普通工具错误不反复解码图片。

诊断与正式重试各占一次原预算，并在 SDK 层关闭隐式重试；普通请求的原重试行为保持。
本地检查和模型调用都受诊断期限/取消约束，前后检查 canonical queue 和上下文是否变化。
成本包含诊断 token；诊断 JSON 不进入助手回答流。现有权限与工具执行路径保持不变。

图片校验缓存结算后只保存普通判定值，空闲释放队列 Promise，本地 codec 工作隔离运行
上下文；冷启动 GC 回归验证不再保留调用方 ALS store。Bun 1.3.10 实测正常 PNG 保持有效、
缺帧 JPEG 返回 invalid；Node bundle 与两种发布归档的四项检查通过。
