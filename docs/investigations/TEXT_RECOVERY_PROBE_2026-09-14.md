# 主 Agent 文字诊断恢复：可行性实验 r1

本次只增加实验脚本，不向生产 Runner/SA/AMA 接入恢复状态机。

## 预注册范围

问题：主 Agent 使用同一个 Provider 实例，把失败上下文投影成纯文字后，能否提出可验证的
附件修复动作，再继续最新任务？模拟 SDK 入口检查已放行但 Provider 仍拒绝图片的情况。
为避免已修复的坏图围栏提前拦截，使用正常 PNG，在客户端传输替身中注入明确定位的 400。
不将这次注入说成真实供应商产生的错误。

- Layer 1：真实 SDK Anthropic/OpenAI 序列化，传输和模型响应使用替身。原样重试应反复失败；
  文字诊断不携带图片/思考签名/原生工具块；恢复仅替换指定附件，保留另一张图、原历史及文件。
- 负例：无定位的 1210、401、错误/不存在的附件 ID、批量删图动作、新用户消息导致快照过期、
  诊断中的悬空工具记录/内嵌媒体，以及恢复仍失败不能递归。
- Layer 1 不能验证真实模型能否理解诊断、提出有效方案并保留最新调价要求，因此做一次
  两通道受控 pilot，每通道只有“诊断→恢复后的文字条款”两轮，不执行任何模型工具调用。
- 两通道：zhipu-coding、zai-coding；模型冻结为 glm-5.3-flash，对应客户案例目标模型。
  每通道并发 1，不同通道并行；模型设置 low effort 仅用于实验。
- 总调用数最多 4，每通道/案例最多 2 轮，每次最多 1024 输出 token、45 秒。
  总 token 预算 20,000；成本占用估算 $0.04–0.40（按内部 probe 估算，并非实际报价/账单），
  使用已有 coding-plan 凭据，不切换计费通道。没有额外模型裁判、自动扩样或 prompt 修补重试。
- 机械检查是动作可执行、定位符合证据、继续文本保留六万元/每项两万元/启动前支付；
  主会话另读原始文本，检查是否虚构文件写入、视觉观察或最新要求丢失。
- 无 prompt A/B 产品优劣比较，无历史 DROP 引用；这是可行性 pilot，不能推导成功率或直接发布。
- 输入/system/响应/工具块/usage/请求 hash 保存在 OS 临时目录，由主会话追加语义评审。

运行：先 `npm run build:bundle`，然后 `node tests/text-recovery-probe.mjs`。
真实模型实验需显式设置 `KODAX_TEXT_RECOVERY_LIVE=1`；凭据从既有环境变量读取，不输出。
脚本不会安装到生产入口，固定附件 ID 是此不可变实验快照的块地址；正式接入需使用实际
请求投影映射，并检查运行/用户输入版本。

## 结果

### 离线：通过

`node tests/text-recovery-probe.mjs` 验证了两种原生协议（Anthropic/OpenAI）的完整请求链：
原始请求失败→原样重试仍失败→文字诊断→仅替换目标附件→继续成功。另验证恢复请求仍失败、
诊断端本身返回 401 时不递归；以及 7 组负例/投影控制。
这里模型回复是确定性替身，因此只证明序列化及恢复执行机制，不证明 LLM 判断质量。
快照未改写，源文件字节未改变，另一张正常图片仍在继续请求中。

最新离线证据：`%TEMP%/kodax-eval-dumps/text-recovery-20260914/r1-jwygRo/offline.json`。

### 真实模型：诊断 2/2，完成继续 1/2

两家均使用同一 Provider 实例完成自己的诊断与继续，没有启动子 Agent/sidecar。
失败 400 及其精确附件地址由实验注入；真实上游只接收诊断和修订后的继续请求。

### 主会话评审与建议

- **任务有效性**：能够回答“同一模型能否从文字诊断材料产生可执行方案，再恢复文字工作”；
  这是请求级原型，不是已经接入 SA/AMA 的完整主 Agent 自愈功能，更不是客户原文档端到端复现。
- **实质价值**：确认不需要额外 Agent 身份。保留 task/system 和用文字表达的失败上下文，
  即可让两家模型给出有效诊断方案；智谱继续输出完整保留最新金额和付款要求，未声称写入文件。
- **定位限制**：本例已经给出可信的精确位置，模型并未自行发现坏图。无位置的 1210 只能
  要求进一步只读检查，当前 guard 会拒绝猜测删图。此前客户日志不能据此视为已自动定位。
- **模型不承担全部正确性**：方案之外仍有运行时验证块地址、证据、上下文版本以及一次恢复预算。
  “模型自己恢复”不等于“模型输出任意指令即可执行”。
- **数据缺口**：Z.AI 继续超时属于本次未完成观测，原因 inconclusive；保留 raw，不通过换模型、
  改提示或加样本把结果包装成成功。诊断本身被拒绝、权限/凭据错误、过长文字、错误工具 schema
  及结果未知的写操作，需要分别处理；纯文字无法消除这些故障。
- **建议：recommend-iterate**。优先围绕主 Agent 的一次文字诊断回合设计最小接入，复用原有
  权限、停止、恢复预算和消息提交机制；暂不实现独立 sidecar。先落实失败上下文快照及请求块
  映射，再讨论允许的恢复动作。仅凭本 pilot 不直接发布通用自动修复功能。

本轮未改任何生产运行时代码。模拟脚本和设计记录是全部新增工作。

## r2：用户要求追加 DeepSeek / Kimi Coding

沿用 r1 相同任务、诊断提示、精确附件证据、动作校验及成功标准，只扩大 Provider 覆盖。
SDK 原生配置路由：deepseek / deepseek-flash（官方 Anthropic 兼容 API，按 token 计费），
kimi-code / k3-256k（Coding 订阅入口）。用户提到的 kimi-coding 在 SDK 中的 ID 为 kimi-code。
本地两协议与负例先重跑；真实模型每通道仅诊断、继续各一次，共最多 4 次，不重跑 GLM。
每次 1024 输出 token / 45 秒、总报告 token 预算 20,000、估算成本预算 $0.40；保留缺失 usage，
无后续模型裁判或自动扩样。low effort 经各 Provider 的原生能力映射发送（不假设不同模型的
实际思考强度一致），并保留 SDK 请求级兼容 headers。

执行：`KODAX_TEXT_RECOVERY_LIVE=1 node tests/text-recovery-probe.mjs --additional-providers`
（PowerShell 使用 `$env:KODAX_TEXT_RECOVERY_LIVE='1'` 设置环境变量）。

### r2 结果与主会话语义复核

离线两协议和 7 组负例/投影控制重新通过。
真实证据：`%TEMP%/kodax-eval-dumps/text-recovery-20260914/r2-UNjpP5/`。
两家各 2 次请求，总共 4 次，均 HTTP 200，合计报告 4141 token；没有追加重试。

| 通道 | 诊断 | 恢复后的实际结果 |
|---|---|---|
| deepseek / deepseek-flash | 约 2.0 秒；正确选择 m2/b0/i1 | 约 6.5 秒；请求恢复，但 stop_reason=max_tokens，1024 输出 token 耗尽，只有开头说明，报价条款未完成 |
| kimi-code / k3-256k | 约 13.2 秒；正确选择 m2/b0/i1，明确保留另一张附件和最新要求 | 约 17.3 秒；end_turn，完整返回六万元、每项两万元、启动前支付的文字草稿 |

DeepSeek 的 `low` 被现有能力配置映射为 `high`，本实验输出预算不足以容纳其思考和完整正文。
这是本次预算造成的截断证据，不能称为修复失败，也不能称为完成任务；未追加请求补齐输出。
后续若验证正式接入，应使用实际任务/模型的正常预算，不能将实验 1024 上限固化到产品中。

Kimi 保留了三个金额/付款核心要求，没有声称已写入新版文档。但正文自行加入“不含税费及
第三方费用”和“未付款不承担延误责任”等未经用户确认的条件。故**模型请求恢复成立**，
**内容不能未经审核直接写回正式文档**。这属于本例语义范围偏移；本次没有正常请求 A/B 对照，
不能归因为恢复机制导致的回归，也不能忽略它而宣称整个业务任务无瑕疵完成。

脚本中的 `status: continued` 只表示恢复后的 Provider 调用返回了响应；任务完成必须另查
stop_reason 和正文。这次主会话复核已据此将 DeepSeek 标为未完成，将 Kimi 的附加条款单列。
旧 r1 的原始输出及结论全部保留。

结论仍为 `recommend-iterate`：四通道均已给出有效诊断；恢复后的请求还需分别处理超时、
输出截断以及模型生成内容偏离要求。本实验只支持同一主 Agent 诊断方案的可行性，未将
诊断/修复自动接入生产运行时，也未验证无位置错误的自动附件定位。

## r3：按用户要求提高 DeepSeek 输出预算

用户明确允许单次测试提高输出预算。只重放 r2 中 DeepSeek 被截断的继续请求，
复用已通过验证的诊断及其生成的 projected history，不重跑诊断、不调用 Kimi/GLM。

仍为原模型及原生 effort 映射、45 秒超时；最多 1 次调用，无重试，报告 token 总预算
20,000，成本占用估算不超过 $0.40。目的只确认先前正文未完成是否由输出预算造成；
审查 stop_reason、金额/付款条款与未授权附加条件，旧截断样本保持不变。

执行：设置 `KODAX_TEXT_RECOVERY_LIVE=1` 后运行
`node tests/text-recovery-probe.mjs --resume-record <r2目录/deepseek.json>`。
