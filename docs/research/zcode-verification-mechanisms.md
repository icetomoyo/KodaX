## 6. 可移植到 KodaX 的设计推断

以下是**设计推断**，不是对 ZCode 运行效果的实测，也不表示本轮要实现。

1. 把验证责任与证据分开：主 agent 负责拿到现场 evidence；artifact skill 规定确定性检查与 render；独立 reviewer 只处理需要 fresh eyes 的视觉/规格问题；goal runtime 决定继续/终止。依据是 ZCode 的上述三条独立路径，而不是给一个万能 verifier 所有职责。[PPT QA](C:/Users/ADMIN/.zcode/cli/plugins/cache/zcode-plugins-official/presentations/0.1.7/skills/pptx/SKILL.md:154)、[browser 观察](C:/Works/PubProj/ZCode/apps/zcode-cli/packages/browser-use-plugin/skills/control-browser/SKILL.md:127)、[goal verifier](C:/Works/PubProj/ZCode/apps/zcode-cli/packages/core/src/runtime/methods/target-completion-verification.ts:133)。
2. 产物需要视觉验收时，先预渲染并提供 PNG + 用户验收项 + 页码范围，再给 reviewer 固定且小的 verdict schema；主 agent 只修具体 evidence 指向的缺陷。避免“主 agent 看一遍、sidecar 又看一遍、完成 verifier 再口头复评”的重复链。[judge 单关口与 schema](C:/Users/ADMIN/.zcode/cli/plugins/cache/zcode-plugins-official/presentations/0.1.7/agents/visual-judge.md:3)。
