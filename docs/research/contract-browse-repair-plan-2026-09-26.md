# 契约与普通历史浏览修复方案

基线 `6e5d6298`。承接[已验证缺陷](product-contract-assurance-2026-09-26.md)与[普通浏览方案](normal-history-browse-fix-plan-2026-09-26.md)。用户授权共同设计并谨慎实施；三名子 Agent 分别负责历史读取、Runtime 生命周期与设置、普通 TUI 浏览，主 Agent 负责整合与终端验收。核心反例已存在，采用公共 Client/真实 Host 和终端的原有验证接缝。

## 选择与边界

| 问题 | 采用方案 | 排除的方案及原因 |
| --- | --- | --- |
| F01 大正文 | 每块解码字节，拼接后统一 UTF-8/JSON 解码 | 拼 base64 会在 padding 截断；逐块转 UTF-8 会破坏跨块字符 |
| F02 单消息多块 | 同一已有恢复函数明确区分完整历史与默认显示窗口 | 提高 150 限制只推迟缺陷；复制一套投影会继续漂移 |
| F03 用户项离窗 | 已有 inputId 规范化显示身份，使用 canonical 来源索引回读 | 不建设无限 ID 注册表，不借正文/时间猜身份；legacy 不借用有身份项 |
| F04 创建失败 | MCP 资源取得即承担清理责任；本次配置与已存在配置分别处理 | 不等所有保存成功才归属；不覆盖/清理旧文件；主错误与清理错误均可诊断 |
| F05 有效设置 | 底层既有 workflow.start 增加明确默认值来源意图；Host 记录并贯穿动态设置 | 不伪造普通 productInput，不对全部低层调用放宽默认，不在 UI 写默认配置 |
| Issue 342 | 普通 owned TUI 内容浏览快照，按需读取同 revision 的有界历史页窗 | 不累计每帧 observe，不提高 Host 窗口，不在每次滚轮全量读取历史 |

ProductClient 业务方法和参数保持不变。必要兼容协商仅用于实际新增的底层工作流默认设置意图；旧 Host 发送前明确拒绝。历史已有来源字段可保留，但跨读取面的显示 ID 不互换，同 outputId 多块不能被误认为一个唯一项。

## UI 行为

向上滚轮/PageUp 在当前内容不到一屏时也代表浏览意图。先保留当前正文，再异步读取已保存历史；成功定位来源后替换浏览内容，失败保留内容并给出恢复操作。正文冻结不冻结运行状态、审批、Stop 或输入。End/明确回到底部、切换 Session/模式、提交新输入使过期读失效。程序性位置夹紧不自动退出浏览。

页窗与正文缓存有界，读取串行：最多 4 页、800 个投影项、200 万字符，另留最多 128 个被逐出新页的 cursor 以支持顺序向下返回。超限保留现屏并提示，不跳过中间历史。大正文的预览不能伪装为全文，也不能仅因一项 oversized 就阻断更早历史。锚点正文至多补读 100 万字符；超大正文尾部不在预览范围时保留原屏。已有 transcript 提供显式全文展开。源位置和 UTF-16 字符位置用于重排/换行锚定，装饰或折叠行保守定位到源项，不承诺它们存在原文字符映射。

追加会使历史 cursor 失效；保留已展示内容、明确刷新，不跨 revision 拼接。没有新增全局事件日志、通用状态机、Host 历史租约或任意旧快照读取承诺。

## 验证责任

- 历史：真实 IPC 的 page/item/search 原文相等；256 KiB 上下和 UTF-8 跨块；160 块顺序及逐项正文；工具高块数及跨页状态/参数。
- Runtime：同文不同 inputId、混合 legacy、普通追加/压缩/rewind；MCP 持久化/Session 保存/清理故障；隐式与显式产品设置实际工具效果、低层对照、旧 Host 门禁。
- UI：真实渲染器与生产 hook 的零高度滚动、分页、源锚、迟到响应、修订失效、模式/Session 切换；原始 160 个独立工具和 100 个独立加 150 个重复工具的终端场景。
- 整合：来源代码及发行构建的 ConPTY 验收，确认真实 Run 终态；覆盖原有 transcript、队列、审批、Stop、断连与退出。注入 SGR/PgUp 是真实终端输入路径测试，不等于物理鼠标硬件验证。
- 代码审查：最终候选树独立 Standards/Spec 双轴评审，修复交叉审查发现后重跑受影响测试。

最终实施和通过情况见[修复验收](contract-browse-fix-verification-2026-09-26.md)；本文保留方案与取舍，不将未执行场景写成已通过。
