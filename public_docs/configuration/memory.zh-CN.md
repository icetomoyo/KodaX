# 记忆

KodaX 会跨会话记住你告诉它的事:你的偏好、你纠正过它的地方,以及代码里看不出来的项目事实。记忆默认开启。

## 工作方式

记忆由一条条笔记组成。每条笔记是一个 markdown 文件,每个存储另有一个 `MEMORY.md` 索引,每条笔记占一行。

| 存储 | 存什么 | 位置 |
|---|---|---|
| 项目笔记 | 关于这个仓库的事实。同一个 git 远端的所有克隆和 worktree 共用。 | `~/.kodax/projects/<project>/notes/` |
| 用户笔记 | 在所有项目里都适用的偏好。 | `~/.kodax/notes/` |

每个会话开始时,Agent 能看到两个索引。只有当某行索引看起来和当前任务相关时,它才会打开那条笔记。笔记不会压过你当前的消息、项目规则,也不会压过 Agent 此刻在仓库里能核实的事实。

## 让它记住或忘掉

直接在对话里说:

- "记住,这个仓库跑测试要用 `make check-fast`。"
- "把关于 pnpm 的那条笔记忘掉。"

Agent 保存笔记时会带上你原话的精确引用,用来证明是你要求的。修改或删除笔记同样需要你的原话。

Agent 也可能在你没要求时记下它注意到的事。这样的笔记是**候选**:在后续会话印证它、或者你批准它之前,Agent 不会读它。这样一次猜错不会影响以后的工作。

密钥和凭据永远不会被保存。

## 后台学习

会话结束后,KodaX 会在后台复盘这次会话。它可以记下你给出的纠正,印证或质疑已有笔记,并为一个确实成功过的流程提议一个技能。提议的技能在你用 `/learn trust <name>` 信任它之前不会被使用。

复盘每天最多调用十次模型。使用 CLI 桥接类提供商(如 Gemini CLI、Codex CLI)时不复盘。嵌入 KodaX 的应用如果提供了自己的学习审查器,复盘也会关闭。

日常整理不调用模型:推断出来、90 天内没人确认也没被用到的笔记会被归档(文件保留),描述相同的笔记会合并。

## `/memory` 命令

| 命令 | 作用 |
|---|---|
| `/memory` | 列出 Agent 会读的笔记,以及每个存储所在目录 |
| `/memory candidates` | 列出它推断出来、尚未确认的笔记 |
| `/memory show <id>` | 完整显示一条笔记 |
| `/memory approve <id>` | 确认一条候选或有争议的笔记,让 Agent 开始读它 |
| `/memory forget <id>` | 删除一条笔记 |

两个存储里有同名笔记时,加上前缀:`project:<id>` 或 `user:<id>`。

笔记就是普通文件,你也可以用任何编辑器直接改。Agent 自己不允许用文件或 Shell 工具写它们。

## 从旧版记忆升级

第一次会话会把旧版本保存的记忆一次性转换成笔记,旧文件原样保留。

想回到旧的记忆系统,设置 `KODAX_MEMORY_NOTES=0`。旧系统只保留到被移除为止。
